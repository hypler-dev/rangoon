# Specification: independent OpenShell observation connector candidate

Status: proposed
Intent: [VUSL design request](intent.md#universal-systems-language-design-request--october-16-2026)
Owner: Jeff
Last updated: 2026-10-20

This is the proposed D2 contract for **one optional, read-only OpenShell connector**. It refines the [provider-independent interoperability boundary](provider-interoperability.md#independent-engine-connectors--october-16-2026) and [operator-record target](operations-control-plane.md#cross-runtime-operator-record-acceptance-target); neither contract is replaced. The retained [historical RUSL D0a research](universal-systems-observation-profile.md) admitted only unverified inert reports; RUSL is retired as an active contract. It is not a prerequisite or a trusted-ingress path for this native connector. Authenticated connected evidence requires a separately accepted trusted-ingress profile and cannot be inserted into D0a by changing its `authenticity` field. Current `openshell_runtime.rs` O0/O1 is historical combined OpenShell/LNSAT research and cannot serve this independent connector.

## Behavior

### User job and invariants

An operator may select an exact OpenShell installation, workspace and sandbox, inspect the native policy that the sandbox reports as effective, then inspect bounded native runtime observations and any gaps. The view answers **what OpenShell reported** for that sandbox and source. It never treats a network/access-rule allow as Rangoon approval, LNSAT authorization, an execution attempt, or a verified external effect. OpenShell's separate policy-change review is identified as policy administration, not approval of every later action. LNSAT is neither installed nor called for this workflow. Local Rangoon import, revision, composition, compilation and export work with no OpenShell connector.

Every evidence row carries a visible source, native identity, policy revision when present, event and receipt times, connection/authenticity state, collection path, and coverage limit. No inferred match on display name, timestamp or trace string joins it to a Rangoon source revision or LNSAT request. An authored-to-runtime relation requires an explicit target artifact/deployment binding and qualified source endpoints under a later relation profile. Unknown remains unknown.

### Native source matrix for OpenShell v0.1.4 research

| Source | Documented fact usable for a future profile | Limit that Rangoon must show |
| --- | --- | --- |

CLI resolution can use environment and active-gateway files; Rangoon must never inherit those defaults silently. |
| [Base/effective policy and revision status](https://docs.nvidia.com/openshell/v0.1.4/how-it-works/policies/manage-policies) | `policy get --base` and `--full` distinguish configured from provider-composed effective rules; `policy list` reports revision/load state. | Gateway acceptance or displayed YAML does not prove latest revision loaded in sandbox. Global policy can replace sandbox policy. Read transport/permission and actual loaded revision need separate qualification; no CLI subprocess is authorized by this design. |
| [Recent `watchLogs` stream](https://docs.nvidia.com/openshell/v0.1.4/sdk/typescript) | SDK documents sandbox log/platform-event stream, cursor resume, warning and `OutOfRange` handling. | Gateway holds a finite volatile buffer; push can drop events. Cursor is opaque and bound to one cursor space. Shorthand lines are not full OCSF JSON. Stream receipt does not prove complete history. |
| [Gateway and supervisor OCSF JSON](https://docs.nvidia.com/openshell/v0.1.4/observability/ocsf-json-export) | Distinct native JSONL/collector paths can preserve structured event IDs and producer class when explicitly configured. | Export is opt-in and best-effort. Gateway JSONL does not archive supervisor lines; sink/queue loss, rotation and replica identity require separate collection evidence. Merely finding a file does not authenticate its origin. |

| [Workload/runtime output](https://docs.nvidia.com/openshell/v0.1.4/observability/accessing-logs) | Container/compute-driver output includes some runtime-origin process/filesystem events and main-process output. | It is not in gateway `watchLogs` or supervisor JSONL; TTY, exec and SSH output differ. Collection may require privileges outside a read-only gateway identity. Absence cannot be called no execution. |

Structured OCSF network activity may report a native action and disposition, including allow or deny. That source is **not** the selected D2b-1 gRPC `WatchSandbox` event schema. D2a's matching labels are synthetic typed-surrogate test data. A later OCSF import or collector packet must pin exact event schema, producer and sandbox scope, opt-in state, authenticity/custody, redaction, retention and loss before Rangoon can show a sourced OpenShell network decision. It still would not establish human approval, LNSAT authorization, complete execution history or external effect.

The released [OpenShell v0.1.4 tag](https://github.com/NVIDIA/OpenShell/releases/tag/v0.1.4) points to commit `5a7728c304b5528e954e9ae900cf21f84e1a12b1` (October 13, 2026). Its [commit-pinned public protobuf](https://raw.githubusercontent.com/NVIDIA/OpenShell/5a7728c304b5528e954e9ae900cf21f84e1a12b1/proto/openshell.proto) supplies a concrete **research schema pin** for D2a; the versioned documentation alone was not an artifact pin. `GetSandboxLogs` and `WatchSandbox` require bearer authentication, `sandbox:read` and workspace `user`; `GetSandboxPolicyStatus` and `ListSandboxPolicies` have the same read gate. `GetSandboxConfig` instead requires `config:read` with dual authentication and workspace `user`, so policy-history access must not silently broaden to full configuration access. `Health` is unauthenticated and cannot stand in for any protected read. This records declared RPC annotations, not a tested credential or authorized live connection.

The same protobuf requires a named workspace selector and canonical sandbox name for one-shot `GetSandboxLogs`. Its response contains chronological lines and `buffer_total`, not a durable-history completeness proof. `WatchSandboxRequest` explicitly distinguishes status, log and platform-event sources, tail limits and an opaque resume cursor. A warning means recoverable skipped items; `OUT_OF_RANGE` means an unrecoverable trimmed cursor or one from a previous restart/replica cursor space, so history has a gap. A cursor the server could not have issued yields `INVALID_ARGUMENT`; that is invalid input, not proof of lost history. The [v0.1.4 log guide](https://docs.nvidia.com/openshell/v0.1.4/observability/accessing-logs) documents a volatile buffer of up to 2,000 lines per sandbox, bounded push loss and separate workload/supervisor output. These are fixture targets and coverage limits for D2a, not current Rangoon ingestion.

The [v0.1.4 Kubernetes HA guide](https://docs.nvidia.com/openshell/v0.1.4/kubernetes/high-availability) describes multiple gateway replicas serving one OpenShell installation with shared PostgreSQL and session-bound forwarding to the replica connected to a sandbox supervisor. That is OpenShell-owned state and topology, not Rangoon storage and not a precedent for pooling independent LNSAT nodes. An observation must retain the exact installation, workspace, sandbox and source identity that the qualified adapter can prove; a gateway replica or cursor-space change produces an explicit continuity gap until native readback re-establishes its scope. Do not infer one cluster from a shared display name or hide a database outage behind a healthy replica.

The [v0.1.4 TypeScript SDK](https://docs.nvidia.com/openshell/v0.1.4/sdk/typescript) documents `watchLogs`, but its package requires authenticated GitHub Packages access and its broader client also exposes consequential and credential-export operations. Do not install it or make it a renderer dependency for this read-only research packet. A later native transport choice must be reviewed against the pinned protobuf, package/dependency safety, exact least-privilege identity and three-OS support. D2a now has a synthetic typed-surrogate fixture and offline conformance checks; it has no native protobuf decoder or source authenticity. D2b still needs separate transport, consent and qualification. No release tag, proto annotation, health response or synthetic fixture alone proves a working connector.

The [v0.1.4 authentication guide](https://docs.nvidia.com/openshell/v0.1.4/how-it-works/gateways/authentication) documents distinct local mTLS-user and OIDC modes. Its `OU=operator` certificate is platform-admin across workspaces and can retrieve provider credentials; that identity is excluded. An initial OIDC-only read transport would serve only a gateway configured for OIDC with a separately provisioned workspace-user identity and `sandbox:read` scope. Default local mTLS and edge-JWT tunnels would remain visibly unsupported until their own transport and credential-custody qualification. The [latest Rust SDK documentation, labeled v0.1.4](https://docs.nvidia.com/openshell/latest/sdk/rust) says its client supports OIDC bearer authentication but not mTLS client certificates; it cannot silently cover those other modes. Rangoon must not borrow OpenShell CLI active-gateway files or token bundles.

## Interfaces and contracts

### Separate operations

| Candidate operation | Input and output boundary | Side effects and gate |
| --- | --- | --- |
| `describe_profile` | Static versioned OpenShell source types, native operation subset, required permissions and known gaps. | Offline data only. Descriptive support never changes a function meter to connected. |
| `validate_configuration` | Bounded explicit endpoint, gateway installation identity, workspace, sandbox reference, product/profile pin and credential **reference**; show destination, data classes and retention before consent. | No DNS/network, ambient gateway resolution, token lookup, file scan or credential read. |
| `check_connection` | One consented endpoint and chosen credential reference; return transport, reported product version, authentication and workspace/sandbox authorization as separate results. | Read-only. Public health is insufficient for protected access; no operator certificate, provider credential export or fallback to a broader role. |
| `read_policy` | Exact sandbox and workspace; separately return base policy, effective policy, revision ID/load status and reported source (including global override) if pinned API permits. | Read-only, bounded. `Loaded` and reported effective policy are separate facts; a version race yields `stale` or `conflicted`, not current enforcement proof. |
| `watch_recent` | One exact sandbox, bounded event/time window, opaque resume cursor and finite retention; output native stream item, source, cursor and gap status. | Explicit start/stop and consent. On warning or `OUT_OF_RANGE`, record lost-history interval; never silently reset cursor or claim continuity. |
| `import_selected_ocsf` | User-selected bounded JSONL snapshot for one named source type, preserving source bytes/digest and parser loss report when storage custody qualifies. | Offline and unverified until source authenticity/collector chain qualifies. No directory crawling or automatic collector setup. Not required for first connected stream. |

The accepted D2a offline packet implements **no network operation**. It inspects finite, inert policy/event fixture fields through a typed mapper and does not mount the D1 parser or O1 record ingestion. The proposed connected packet below chooses a pinned read transport; minimum permission must be proven before host mounting or any live target. A general URL or command field is forbidden. The native host, never the renderer, owns consent, credentials, bounded reads, identity validation and storage. No operation submits policy, creates a sandbox, exports credentials, invokes middleware, executes a tool, or grants approval.

### Provenance and projection

Preserve native producer and affected sandbox as different identities. Scope a native event by selected gateway installation, workspace, sandbox ID, producer/source kind, native schema/product version and native event ID if supplied. Gateway name alone is insufficient across installations or replicas; retain replica identity when present. Keep provider event time and Rangoon receipt time separate. An opaque `watchLogs` cursor is stream-custody metadata, not an event ID or cross-source join key. A redacted digest proves only selected bytes equal; it does not prove authenticity, lossless translation or effect.

Map a native policy decision only to provider-policy evidence. Map a policy-change review only to policy-administration evidence. Map a native runtime result to a **reported** result or attempt only if the pinned source actually says so. When source fields are absent, retain native data opaquely with visible loss, or refuse translation of a mandatory field. The O1 operations window remains its local record owner; a later ingress profile must name exact O1 mapping rather than create a second authoritative history. D0a's unverified observation may display a sanitized offline fixture but cannot claim authenticated OpenShell evidence. Never copy an OpenShell ID into an LNSAT `authorization_id` or merge equal native strings across engines.

## States and failure handling

| State | Required operator meaning and action |
| --- | --- |
| `unavailable` | Connector absent; local workbench remains usable. No network attempt. |
| `unsupported` | Pinned product/protocol/source shape or requested operation incompatible; show exact missing capability. No fallback parser. |
| `disconnected` | Explicit endpoint not reachable after consent; retain last observations as historical and mark current status unknown. |
| `authentication_failed` / `permission_denied` | Separate bad/expired caller identity from authenticated caller lacking workspace/sandbox read scope. Do not retry with ambient credentials or operator/admin role. |
| `stale` / `conflicted` | Product/policy/revision/identity drift, concurrent policy change or conflicting native events. Preserve both facts; current effective coverage unassessed until requalified. |
| `gap` / `history_unknown` | Stream warning, `OUT_OF_RANGE`, restart/replica cursor-space change, bounded-buffer overflow, collector drop, unavailable workload logs or unknown earlier window. Show exact known window and source; no continuous audit badge. |
| `error` | Malformed, over-limit, timeout or source error with bounded diagnostic. A timeout after a read may leave observation incomplete; it says nothing about external effect. |

Internal pending-state readback reuses the existing Host state: a current awaiting review reports `AwaitingConsent`; a current confirmed review reports `ReadyForNativeCredential`; an expired selection reports the fixed `CredentialLeaseExpired` error; a fenced workspace generation reports `Unavailable` before either phase or expiry. Readback is observational and does not consume a reference, renew a deadline, release admission, obtain a credential or start a client. Expired pending custody remains retained until explicit Stop or the existing close path. `ReadyForNativeCredential` describes the review phase only; it is not credential presence, provider connectivity, action approval or execution permission. This corrects the existing C0/C1 state contract without mounting a command or changing `begin_production` availability.

The view distinguishes `not observed`, `source unavailable`, `unsupported`, `not required by this provider` and `verified absent within a qualified finite source/window`; only the last has a proof obligation. An allowed policy rule and a denied request may coexist under different revisions or targets and must remain separate. A changed policy does not rewrite earlier native events. Repeated native IDs within one source become conflict/dedup diagnostics according to the pinned producer contract, never a best-looking winner. Any UI graph has a keyboard-accessible table and exact-source inspector; decorative motion cannot fill missing edges.

## Data, privacy, and permissions

Default to selected sandbox metadata, policy rule summaries and redacted event fields. Raw policy YAML, log lines, request paths, headers, model content, tool arguments and credentials may contain sensitive data; retain only under an accepted encrypted-workspace custody/retention profile with explicit selection. Do not transmit or save provider secrets in VUSL, the renderer, diagnostics or telemetry. No background discovery, provider installation, unbounded watch, automatic OCSF enablement or remote model inspection. Connected reads require explicit destination, credential reference, data preview, scoped consent and revocation/stop control. In particular, OpenShell's mTLS operator identity can export provider credentials and is too broad for this read-only connector; it is excluded. Gateway authentication, authorization, transport trust and native event authenticity are separate checks.

## Compatibility and migration

This candidate does not mutate I1's eight-entry authority catalog, A1's LNSAT port, O1/O2 records, or the historical O0/O1 `openshell_runtime.rs` schemas. A new OpenShell-specific observation profile/version is additive. No automatic migration from combined-path fixtures is allowed. On downgrade, changed product/schema/policy/identity pins, missing critical source fields or unsupported extension, refuse the affected interpretation and preserve prior historical observations with their old qualification label. Local no-provider workflows and three-desktop release gates remain independent.

### D2a internal offline source packet — accepted

Jeff accepted the exact internal D0a review snapshot for an offline OpenShell fixture adapter; [intent](intent.md#internal-d0a-profile-and-d2a-offline-adapter--october-17-2026) owns its file hashes and scope. One bounded implementer owns new `crates/rangoon-integrations/src/openshell_observation.rs`, new `crates/rangoon-integrations/tests/openshell_observation.rs`, and new `fixtures/openshell-observation/v0.1.4.json`; root owns only necessary `lib.rs` wiring, contract review and validation. No new dependency is required. Do not edit or reinterpret historical `openshell_runtime.rs`, O1/O2 schemas, A1, or LNSAT. The fixture file is a **synthetic typed surrogate** for selected fields from the pinned OpenShell protobuf, not a captured native message, binary protobuf decoder, authenticated source, or supported transport. D2b must separately qualify protobuf decoding and host custody against the same release pin. Internal profile acceptance does not accept a public D0a wire or mount D1 into the native host.

The pure D2a mapper would accept one bounded, already decoded window plus explicit installation, workspace, sandbox and source scope. It may inspect `GetSandboxPolicyStatusResponse`/`SandboxPolicyRevision`, bounded `GetSandboxLogsResponse` lines, or bounded `SandboxStreamEvent` status/log/platform/warning variants. It must preserve revision versus `active_version`, pending/loaded/failed/superseded meaning, provider event time versus local fixture time, source kind, replica/cursor-space identity when supplied, and a fixed loss list. `PENDING` is not loaded and cannot establish effective policy. It cannot silently infer global effective policy, complete history, native event identity, an authorization, or an external effect from these fields. Plain log `message`, full policy YAML, arbitrary structured fields and credentials stay out of mapped output; unknown critical fields or unsupported versions cause `unsupported`/`unassessed`, not downconversion. D0a output, if any, must go through the accepted `rangoon-language` inspection contract; the mapper cannot fork its canonicalization or validate a provider identity by constructing a plausible D0a object. No O1 write or operator graph join belongs to this packet.

Freeze D2a limits: the production mapper accepts **typed values only**, never raw JSON/protobuf bytes. One window contains at most 128 metadata items and at most 32 policy revisions; each present identity, revision, native event ID, replica ID and cursor-space token is 1–128 ASCII bytes from `[A-Za-z0-9_.:-]`. A missing native event ID stays missing with a fixed loss reason; the mapper must not fabricate or deduplicate it. An opaque cursor is separate stream custody, at most 512 UTF-8 bytes without controls; it is neither parsed as an identity token nor used to join events. A gateway display name is untrusted descriptive text, at most 256 UTF-8 bytes and never an identity key. Timestamps are separate optional nonnegative millisecond integers no larger than `2^53-1`; missing/contradictory times remain visible. No log message, policy YAML, arbitrary OCSF object, URL, credential or payload is accepted by this typed seam. Serialized minimized output is at most 131,072 bytes. Over-limit input/output fails the whole window with a fixed diagnostic, never truncation or best-effort partial success. The test-only synthetic JSON fixture is at most 262,144 bytes; fixture loading does not become production file I/O. These are per-window safety bounds, not fleet throughput/storage limits.

Pin fixture cases for same-name installations with colliding native IDs, one-installation repeated/conflicting IDs, different gateway replicas, policy revision pending/loaded/failed/superseded, active-versus-queried version mismatch, denied/allowed reports, changed policy, log-buffer truncation, watch warning, `OUT_OF_RANGE` for trimmed or old-space cursors, `INVALID_ARGUMENT` for a never-issued cursor, missing workspace/sandbox, missing event ID, mixed producer kinds, malformed/oversize input and an uncertain reported result. Every case asserts source-qualified identity, correct gap versus invalid-input status, no invented cross-engine relation and no execution authority. The validator set is locked/offline focused Rust conformance, existing D1 and I1/O1 regression, `cargo fmt --all --check`, focused warnings-denied Clippy, workspace tests, `npm run build:check`, `node scripts/validate-review.mjs`, `git diff --check`, and fresh independent source/security review. D2a opens only inert fixture inspection; D2b needs its own later host/transport packet.

### D2b-1 native connected-read transport packet — accepted for unmounted source

**Purpose and boundary.** Jeff accepted this exact source packet on October 17, 2026. The first connected implementation slice is a Rust-owned, read-only OpenShell v0.1.4 gRPC client that can inspect one explicitly selected installation/workspace/sandbox. This is transport engineering, not another fixture-to-UI substitute. It stays unmounted while tested against a disposable synthetic gRPC peer. No user provider, live destination, production credential, renderer action or live support claim is authorized. D2b-2 must separately accept native host consent, secure credential reference/lease, encrypted observation custody and user-facing start/stop; D2b-3 must qualify a disposable released gateway and macOS/Windows/Linux native clients before a connected-support badge. The provider-free workbench never waits for any D2b stage.

**Pinned subset and exact ownership.** Recheck the selected v0.1.4 tag, commit-pinned protobuf and its imports, operation annotations, dependency licenses and minimum Rust version at packet start. One transport owner would create `crates/rangoon-openshell-client/` with the exact pinned proto source set and hash receipt, private generated client bindings, one closed method allowlist, a distinct native-read projection, transport implementation and fake-peer conformance tests. Root would own only `Cargo.toml`/`Cargo.lock` workspace wiring, source-provenance and integration/security decisions, and this status record. Keep `crates/rangoon-integrations/src/openshell_observation.rs`, I1/A1/O1/O2, `openshell_runtime.rs`, desktop commands and preview unchanged in D2b-1. D2a's output is permanently labeled `openshell_offline_synthetic`; no connected read may pass through it or relabel it. The new D2b-1 output is a bounded native-read candidate with selected scope and explicit **unqualified source authenticity** until the later trusted-ingress/host gate. Do not expose raw generated stubs, arbitrary method names, general URLs or policy/configuration writes to the renderer. Library consumers receive only `check_protected_read`, `read_policy_status`, `read_recent_logs`, `watch_recent` and `stop` over an exact configuration selected by a future native host. The client must never call `GetSandboxConfig`, provider-credential retrieval, sandbox lifecycle, policy mutation or any LNSAT route.

**Authentication and network contract.** First profile is OIDC bearer over authenticated TLS only, with a separately supplied short-lived secret lease and explicit HTTPS origin, installation identity, workspace and sandbox; a future host must obtain consent before constructing it. No discovery, OpenShell CLI subprocess, active-gateway/environment fallback, implicit proxy, redirect, insecure TLS, token refresh, operator/admin role or credential logging. Restrict DNS/IP selection and connection reuse to the consented destination; reject a changed peer, host, certificate or product/protocol pin. Treat `Health` as reachability/version only; require a protected sandbox-scoped read to distinguish authenticated from authorized, and never infer an identity's privileges from the token text. Return separate unreachable, TLS, unauthenticated, permission-denied, unsupported, cancelled, stale and source-error states. A fake peer can test these boundaries but cannot qualify a real OpenShell identity or release.

**Bounded stream and mapping.** Expose and call only `Health`, `GetSandboxPolicyStatus`, `ListSandboxPolicies`, `GetSandboxLogs` and `WatchSandbox`, where the pinned annotations permit the selected least-privilege caller; keep any additional generated methods private and unreachable from the wrapper. Require the named workspace and sandbox on every protected request, `global=false` on policy reads, an explicit finite policy page size and bounded one-shot log/tail sizes. Enforce per-RPC deadlines, message sizes, total window item/byte limits, finite watch duration and an explicit cancellation token before accepting any provider bytes. Preserve source kind, installation/workspace/sandbox, native IDs, policy revision and load status, source/receipt times and opaque cursor as separate fields in the **new D2b projection**, after strict native decode and scope checks. D2a's synthetic mapper may guide field comparison in tests but must not receive or emit connected evidence. If the wire supplies no installation ID, keep that part caller-declared/unverified until a later qualified binding, rather than upgrading it from a display name. Use a closed field allowlist: discard raw log messages, full policy bodies, `SandboxPolicyRevision.load_error`, its arbitrary `provenance` map and other free-text/unknown fields; a failed load becomes a fixed diagnostic class with explicit loss, never a provider string. This subset inspects policy **revision/load metadata** and finite runtime stream status, not composed effective policy content or per-action allow/deny decisions. Those user jobs remain unsupported until separate least-privilege structured read sources qualify; free-form log/event text cannot fill them. On watch warning, overflow, restart/replica change or `OUT_OF_RANGE`, emit a visible continuity gap. Local cursor validation can return `invalid_cursor`; the provider's `INVALID_ARGUMENT` is ambiguous because it can also reject scope or another request field, so the client returns a fixed source error rather than attributing cause from provider prose. No automatic cursor reset, unbounded replay, silently dropped event or fabricated execution effect.

**Conformance and exit.** Fake gRPC peer covers each allowed method and proves no other method is invoked; public-health success plus protected denial; wrong workspace/sandbox, version and policy revision; malformed/over-limit frames; missing event IDs; text that says “allowed” or “denied” must remain unclassified free text, never a decision; duplicate and cross-installation IDs; bounded tail, warning, `OUT_OF_RANGE`, `INVALID_ARGUMENT`, slow/stalled stream, cancellation, disconnect and changed TLS peer. Put secret-like text in log messages, policy bodies, `load_error`, provenance maps and unknown fields; assert only fixed diagnostic/loss classes leave the projection. Assert no D2a `openshell_offline_synthetic` output is relabeled as connected, no unqualified D2b record gains `authenticity=verified`, zero credential/URL/raw-payload leakage in output and errors, zero write RPCs, zero LNSAT calls, no automatic approval or cross-engine edge, and unchanged provider-free authoring/export. Run locked focused and workspace Rust tests, formatting, warnings-denied Clippy, native build checks where available, `npm run build:check`, document/reference checks and fresh independent source/security review. Passing synthetic tests qualifies source behavior only. D2b-2 and D2b-3 remain separate accepted gates; no green connected badge, “live” graph or continuous-history claim follows.

### D2b-2 native host consent and observation custody — proposed packet

**Status and ordering.** Jeff accepted D2b-2a for source implementation on October 17, 2026; D2b-2b remains proposed and D2b-3 remains a separate qualification gate. D2b-1 acceptance does not itself authorize host mounting. Use the existing native workspace-generation admission, single-attempt consent custody and closed client wrapper; do not create a parallel session, database or authorization engine. D2b-2a covers host control against synthetic peers with dummy test leases and production Start closed. D2b-2b separately requires qualified native-only credential acquisition, encrypted observation save and native UI, because the current Managed factory and three-OS GUI path are not qualified. A D2b-2a pass cannot claim durable evidence or a usable connected screen. D2b-2b cannot begin by falling back to Legacy plaintext or a webview secret form.

**Operator flow and authority.** A later main-window operator selects one exact HTTPS gateway origin and explicit peer IP/port, trusted root and leaf pin, installation/workspace/sandbox, pinned product version and one bounded `ReadKind` (`protected_check`, `policy_status`, `recent_logs` or `recent_watch`). Native offline validation displays both the origin and selected socket plus data classes before any network call. The first profile never resolves DNS itself; changing the selected socket or TLS peer requires a new review, never an automatic substitution. D2b-2a uses only test-injected dummy bearer leases. Production credential acquisition remains unavailable until a separate native-only input or host-owned opaque OS-secret reference design is accepted and tested on all three OSs; an isolated webview is still a renderer and may not receive a provider bearer. The main window receives only an opaque native reference when that later gate opens. The host owns a zeroizing lease with a short monotonic maximum lifetime; user-supplied expiry metadata is an additional upper bound, not proof of identity or scope. No ambient CLI, environment, browser session, global keychain lookup, refresh flow, operator certificate or admin fallback is allowed. Native one-shot confirmation must bind exact destination, pin, scope, `ReadKind`, data classes, retention mode, workspace generation and credential reference. A claimed reference and its consent are single-use. Renderer confirmation alone has no effect. The first protected read, rather than public Health, reports whether authentication and sandbox read permission work. Consent to read grants no policy, approval, execution or LNSAT authority.

**Session-only first slice (D2b-2a).** Host operations are closed: validate a bounded proposed target without I/O; prepare exact native review; confirm or cancel; begin a finite read; stop; inspect a minimized status/result. Production begin returns `unavailable` until native-only credential acquisition is accepted; only tests inject dummy bearer leases and synthetic TLS peers.
