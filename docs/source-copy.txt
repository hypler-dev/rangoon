Understand what they can do. Reuse capabilities across projects. Test behavior before deployment. Apply policy at every consequential boundary. Move agent capabilities between supported harnesses without rebuilding everything from scratch.**More capability. Less risk. Greater possibilities.**[Explore Rangoon](#what-is-rangoon)  [View on GitHub](#open-source)  [Learn about LNSAT](#powered-by-lnsat)> **Rangoon is currently in active development.**> Product interfaces, supported harnesses, and extension contracts may evolve before the first stable release.---# What is Rangoon?Rangoon is an open-source management and orchestration layer for governed AI agents.It sits above individual AI harnesses and provides one place to manage the assets that make an agent useful:- agents- skills- instructions- context- rules- workflows- tools- connectors- memory configuration- policies- approvals- runtime assignments- deployment targets- tests- versions- audit evidenceRangoon does not replace the underlying AI models or agent harnesses.It helps you manage them.A team may use Claude Code for one workflow, Codex for another, Gemini CLI for another, and a custom runtime for production agents. Rangoon provides a common layer for composing and governing the capabilities that move between those systems.---# Compose. Govern. Test. Deploy.## ComposeTurn instructions, skills, tools, workflows, and agent configuration into modular, reusable assets.Rangoon treats agent capabilities as software rather than loose prompt text.Import existing agent projects or create new capabilities inside the platform. Decompose large instruction files into reusable pieces. Merge overlapping skills. Split complex skills into focused modules. Build complete agents from versioned components.Everything maintains provenance, dependency information, compatibility metadata, and version history.## GovernCapability does not equal authority.Rangoon integrates policy directly into agent composition and operations so teams can define what an agent may request, which tools it may access, when human approval is required, and how sensitive actions move through governed execution.Policies can apply to agents, skills, workflows, connectors, environments, data classes, and deployment targets.Policy changes can be reviewed, simulated, approved, staged, rolled out, and rolled back.## TestAgent configuration is probabilistic. Testing cannot be an afterthought.Rangoon provides a Test Lab for evaluating activation behavior, instruction adherence, tool selection, output structure, policy behavior, compatibility, performance, and cross-harness consistency.Run the same capability against multiple supported harnesses and compare how each environment behaves before deployment.## DeployCompile canonical Rangoon capabilities into the formats required by supported agent harnesses.Preview generated files, inspect transformations, validate compatibility, review warnings, approve changes, and deploy exact versioned bundles to approved targets.Deployment, activation, permission assignment, and authorization remain separate operations.---# The Command Center## One place to operate your LNSAT?Agent management and execution authority solve related but different problems.Rangoon answers:> What agents do we have?> How are they configured?> Which skills do they possess?> Which workflows use them?> Where should they run?> How should these assets evolve?LNSAT answers:> What exactly is being requested?> Who or what requested it?> Which policy applies?> Is approval required?> Is this exact execution authorized?> What evidence proves what happened?Keeping these layers separate allows other products to build on LNSAT while allowing Rangoon to focus on delivering an excellent agent-management experience.---# Security PrinciplesRangoon is designed around several core principles.**Configuration is not authority.**Giving an agent a skill does not silently grant the right to perform every action described by that skill.**Installation is not enablement.**Installing a connector or extender does not start it or assign access.**Enablement is not permission.**A connected system is not automatically available to every agent.**Detection is not truth.**AI-assisted capability detection produces evidence-backed suggestions subject to deterministic validation and human review.**Compilation is not deployment.**Generating harness artifacts does not make them active.**Deployment is not execution authorization.**A deployed agent must still pass applicable execution-time authority checks.**Policy outranks advisory models.**Models may classify, explain, recommend, or escalate. They do not silently override deterministic policy.---# A Platform for an EcosystemRangoon is one product built on LNSAT.It should not be the only one.We want developers, companies, and open-source communities to build different systems on the same authority foundation.Possible products built on LNSAT might include:- coding-agent platforms- infrastructure agents- financial automation- autonomous research systems- security operations- healthcare workflow systems- internal enterprise agents- robotics management- domain-specific copilots- custom agent runtimesRangoon represents our approach to agent management.LNSAT remains the common trust layer.---# For Developers## Extend the platform without rewriting it.Developer-facing Rangoon interfaces are planned around versioned extension points.Build:- skills- harness adapters- connectors- workflow nodes- policy packs- test packs- model profiles- UI extensions- deployment adaptersRangoon should make third-party capability visible, inspectable, versioned, and governable.---# Harness Adapter SDKHarness adapters teach Rangoon how to:- discover native configuration- import supported assets- map native concepts into Rangoon's canonical model- report supported functionality- compile canonical assets back to the native format- test generated output- detect version compatibilityHarness behavior changes quickly, so adapters should be versioned independently from the core platform.---# Connector SDKConnectors expose external systems through explicit operations rather than unrestricted ambient access.A connector can declare:- supported operations- required inputs- expected outputs- required credentials- network access- side effects- idempotency requirements- receipt behavior- policy-relevant metadataLNSAT remains responsible for deciding whether an operation may execute.---# Capability Intermediate Representation## One canonical model. models and harnesses.## Is Rangoon an agent framework?Rangoon includes agent-management and orchestration functionality, but its primary role is broader: managing the lifecycle, portability, governance, testing, and deployment of agent capabilities.## Does Rangoon replace Claude Code, Codex, Gemini, Copilot, Cursor, or Windsurf?No.Rangoon is designed to manage capabilities across compatible harnesses while preserving target-specific behavior.## Does every harness support every Rangoon capability?No.Rangoon explicitly models compatibility and adaptation instead of pretending all runtimes provide identical functionality.## Is Rangoon open source?Rangoon is intended to be primarily free and open source, with optional commercial extenders and enterprise services.Final licensing and package boundaries will be published before stable release.## What is LNSAT?LNSAT is the independent open-source execution authorization and evidence engine underneath Rangoon's governance model.It evaluates authority for consequential agent actions and produces evidence around the decision and execution path.## Can LNSAT be used without Rangoon?Yes.LNSAT is intended to support other agent-management products and custom integrations independently of Rangoon.## Can Rangoon work without LNSAT?Some management and composition functions may technically operate independently, but governed execution is designed around LNSAT.## Can I import existing agent configuration?That is a core design goal.Rangoon is being designed to discover, analyze, normalize, and manage existing agent configuration rather than requiring every project to start over.## Can Rangoon move skills between AI tools?Cross-harness portability is a central goal.Rangoon will use versioned adapters to import and compile supported capability types for compatible harnesses.## Does Rangoon execute imported scripts during discovery?No.Discovery and analysis should treat imported scripts and configuration as untrusted input.Importing content does not automatically execute it.## Does installing a connector give agents access?No.Installation, enablement, credential assignment, permission, policy authorization, and execution are intentionally separate concepts.## Who is Rangoon for?Rangoon is being
