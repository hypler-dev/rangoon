## Trust and API

`relate_window(&DecodedWindow) -> Result<Relationships, RelationshipError>` is the only public constructor. No public deserialization/construction/mutation, I/O, clock, authentication, policy evaluation, grant issuance, authority or execution. Private wrapper exposes canonical_bytes(), canonical_digest() and document(); serializable private-field DTOs are read-only. Wrapper Debug exposes digest/byte count only. Exact structural v1 bytes/meaning remain unchanged. The function first calls project_window on the same immutable decoded window; it never accepts a caller-built Projection or trusted JSON flag.

Output fixes authority none, authenticity unverified, execution unavailable, semanticAssessment reported_links_only, authoritativeEligibility unknown and authoritativeEffectiveEvaluationId null. `reportedChainTipId` is an internally consistent, unverified observation selector, never O0's trusted effective evaluation or eligibility. Reported allow/approve/issued/verified/full coverage cannot alter these rails. A deny/unknown evaluation remains its reported result even if all decisions say approve. Shape, hashes and internally agreeing records do not authenticate identity or external evidence.

Fixed payload-free error codes: relationship_serialization_failed, relationship_structural_limit (upstream ProjectionError::Limit), relationship_limit. Other upstream errors map to serialization_failed. No raw parser prose, input keys/values, paths or payload excerpts. Input remains immutable on every failure. Output capped at 1,048,576 bytes via a bounded writer before buffer growth. At most 8,192 reference rows and 8,192 combined matching-event ordinals across all references and chains; check before cloning/pushing beyond budget. Every budget exhaustion fails atomically; no partial relationships or diagnostic omissions.

## Exact output schema/order

Schema rangoon.ops.relationships.v1. Top-level ordered fields: schemaVersion, inputCanonicalDigest, structuralProjectionDigest, authority, authenticity, execution, semanticAssessment, authoritativeEligibility, authoritativeEffectiveEvaluationId, diagnosticCounts, eventLinks, chains. Digests bind exact decoded-window and structural-projection bytes; internal consistency only.

One eventLinks entry per input event, sorted inputOrdinal ascending. Ordered fields: inputOrdinal, eventId, recordId, recordKind, assessment, diagnostics, references. Five selected kinds request/evaluation/approval_plan/approval_decision/authorization receive assessed links. Other fourteen kinds have assessment not_assessed, no diagnostics/references; their exact records remain available through O1a/O1b-1 and may be selected dependencies. This does not drop their observations or qualify those records.

Reference row ordered fields: field (fixed selector below), index (nullable list index), recordId, expectedKind, status, matchingEventOrdinals. Status unique_unverified if all matching typed record bytes are identical and expected kind agrees; missing if absent; ambiguous if any matching record bytes differ; wrong_kind if one unique record's kind disagrees. Ambiguous wins wrong_kind. Preserve every matching observation ordinal ascending, including byte-identical duplicates. Repeated list IDs produce separate indexed reference rows. Null optional references produce no row. Reference ordering is table order below, then input list order.

Chain rows sort (requestId, engineId) lexicographically. Ordered fields: requestId, engineId, requestEventOrdinals, evaluationIds (distinct sorted IDs), reportedChainStatus (single_chain_unverified, unknown_or_conflict or no_evaluation), reportedChainTipId nullable, reportedResult nullable allow/deny/unknown, diagnostics. One row per distinct (context.requestId,context.engineId) represented by any selected record, at most 1,024. Request lookup retains every matching ordinal even if wrong kind/ambiguous; its reference budget counts toward combined 8,192 matches. No_evaluation applies only to a unique, linked request with zero evaluations and no core diagnostics; otherwise unknown_or_conflict. Single_chain_unverified requires every request/evaluation core check below to pass. The exact core diagnostic set is all fifteen relationship codes except informational non_tip_evaluation; any such flag on a request/evaluation blocks candidate selection and no_evaluation. Tip result is copied from the selected evaluation, independent of approval decisions. Chain diagnostics union request/evaluation flags plus group flags in table order; no approval result can change evaluation result.

## Structural propagation and reported evaluation chain

Index immutable records by record.id and canonical typed bytes; differing bytes are ambiguous, identical repeats idempotent for candidate selection while every event stays inspectable. Exact stream-taint set: event_identity_conflict, sequence_conflict, record_identity_conflict, sequence_gap, predecessor_missing, predecessor_conflict, prefix_fence_mismatch, prefix_watermark_mismatch, prefix_identity_conflict, scope_mismatch, correlation_mismatch. These taint an entire producerId/fenceId stream; duplicate_observation and the six graph-only codes do not. Selected records inherit structural_incomplete from their own stream or any referenced observation stream. Snapshot prefix_watermark_mismatch/prefix_identity_conflict taint all selected links/chains conservatively. Graph-only diagnostics do not establish evaluation causality and do not taint link selection. No partial causal-local interpretation of a gapped producer stream.

For each group collect unique evaluation records whose context names that requestId/engineId. A conflicting identity, missing/wrong-kind request or any request/evaluation core diagnostic forbids candidate selection. For each evaluation, every observed occurrence must use event.fenceId == evaluation.lineageFenceId and the same producerId/fenceId pair; repeated same immutable evaluation may have later stream sequences. Compare earliest sequence of each evaluation when assessing succession; do not pick by timestamps or input order. producerId is never compared to a fence ID.

Initial evaluation requires previousEvaluationId and expectedEffectiveEvaluationId null. Successor requires both nonnull and equal. Predecessor must uniquely resolve as evaluation in the same group/FlowKey, same gatewayRevisionId, same lineageFenceId and same producer/fence pair; successor earliest sequence must exceed predecessor earliest sequence. Exactly one initial root and at most one distinct successor per evaluation. Iteratively walk from root through successors, at most 1,024 hops, with a visited ID set; all group's unique evaluations must be reached. Missing predecessor, invalid selector, mismatched context/gateway/fence, nonmonotonic sequence, multiple roots/competing successors, cycle or disconnected history makes status unknown_or_conflict and tip/result null. Do not choose a surviving branch or erase other evaluations. Exact repeats do not add roots/successors.

When a chain has single_chain_unverified, plan/decision/authorization bound to another evaluation in that same group gets non_tip_evaluation. This is historical display information, not valid/invalid approval or a rebinding path. No decisions/plans/authorizations are carried to a successor. Unknown chain leaves that relation unassessed rather than choosing the newest event. Source authenticity always remains unverified, so no authoritative currentness claim follows.

## Fixed diagnostics and assessments

Arrays and diagnosticCounts fields use this exact order. Counts includes zero for every code and counts affected eventLinks plus chain rows once per code per entry. Reference statuses do not add a second diagnostic count. Informational non_tip_evaluation does not make a link conflicting.

| Code | Exact meaning |
| --- | --- |
| structural_incomplete | Relevant stream/global prefix taint described above |
| reference_missing | At least one required emitted reference has no matching record; chain request lookup can also be missing |
| reference_ambiguous | Matching same-ID typed records disagree |
| reference_kind_mismatch | Unique referenced record has wrong kind |
| context_mismatch | Unique referenced FlowContext differs in FlowKey |
| gateway_mismatch | Evaluation gateway differs from request, or predecessor evaluation gateway differs |
| context_digest_mismatch | Evaluation contextDigest differs from request |
| gateway_policy_mismatch | Request gateway's pinned policy or gateway identity differs from request/policy record |
| evaluation_selector_mismatch | Initial/successor predecessor/null/expected selector rule fails |
| lineage_fence_mismatch | Evaluation occurrences disagree on producer/fence, event fence differs from declared lineage fence, or predecessor differs on lineage/producer/fence |
| evaluation_sequence_mismatch | Successor earliest sequence is not greater than predecessor earliest sequence |
| evaluation_branch | More than one initial root or distinct successor at any predecessor in group |
| evaluation_cycle | Repeated ID in bounded iterative predecessor walk from any evaluation; no recursion |
| evaluation_incomplete_chain | Group cannot reach all evaluations from exactly one root; zero roots with nonempty evaluations also qualifies |
| binding_mismatch | Decision plan/evaluation/stage or authorization plan/decision/evaluation rules disagree |
| non_tip_evaluation | Historical plan/decision/authorization references a different evaluation from a known reported chain tip |

assessment priority: not_assessed for other kinds; ambiguous if reference_ambiguous; conflicting if any context/gateway/digest/policy/selector/fence/sequence/branch/cycle/incomplete_chain/binding flag; missing if reference_missing or reference_kind_mismatch; structurally_incomplete if structural_incomplete; otherwise linked_unverified. non_tip alone stays linked_unverified. Group-only branch/cycle/incomplete-chain flags are also marked on all evaluation entries in that group; do not pretend one competing evaluation is current. Candidate selection tests request/evaluation core diagnostics only; a malformed approval does not replace the reported evaluation result, and cannot confer authority.
