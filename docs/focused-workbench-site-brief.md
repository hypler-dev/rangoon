# Rangoon and Hypler: focused product messaging

Status: owner-requested positioning and site-update brief, October 22, 2026. Copy only; no sites published by this packet.

## Product direction

Rangoon is a local-first capability workbench: import existing agent instructions, organize reusable skills, compose versioned inputs, prepare inspectable exports and review available evidence. Its next proof is what an external executor actually loaded and ran. Reuse qualified execution/automation products rather than building another complete agent platform. Jeff is Customer Zero for the general product; Hypler infrastructure remains private configuration.

## Rangoon site copy

Suggested headline: **Make agent capabilities reviewable.**

Suggested subheading: **Bring instructions into one workbench. Organize reusable skills, compose versioned capabilities, and keep source-to-output history visible.**

Primary actions: **Explore the workbench** and **View development on GitHub**. The first action should point to an explicitly labeled preview or documented build, not imply an available production installer.

Three product pillars:

- **Author and compose:** review source sections, edit reusable skills, combine selected revisions and inspect the resulting instructions.
- **Trace changes:** retain source provenance, revision history and source-to-output mappings.
- **Inspect evidence:** review supported local/imported evidence with explicit source and coverage. External execution and effective-configuration verification are being qualified separately.

Short development note: **Rangoon is in active development. Local workbench components are implemented; connected execution and cross-system verification are being qualified individually.**

Integration card wording: **OpenHands — execution adapter under evaluation.** SDK/Agent Server is the first reuse candidate; Automation is a separate beta scheduling candidate. No supported integration badge until its named test passes. Optional future integrations may consume existing observability/authorization services; do not list research candidates as working connectors.

## Hypler portfolio copy

**Rangoon is Hypler's local-first capability workbench for organizing agent instructions, composing reusable skills and inspecting their provenance and evidence. Its development focuses on interoperability with existing execution systems, beginning with an isolated OpenHands adapter evaluation.**

Keep the three projects distinct:

- **Rangoon:** capability authoring, composition, review and operator visibility.
- **LNSAT:** independently developed authorization and evidence engine.
- **VUSL:** independently developed semantic interoperability project.

These descriptions state product roles, not released integration or certification claims. Use each project's own logo and repository reference. Rangoon's useful local authoring does not require either other project.

## Site sections to adjust

Lead with the workbench and its source → skill → composition → export journey. Feature screenshots should show populated real local workflows when qualified, or carry a clear sample label. Put engine catalogs, infrastructure/fleet management, scheduling, budgets, broad plugin coverage and experimental 3D views into a roadmap or technical detail section. Preserve the existing abstract art direction without spending this milestone on new artwork.

Do not claim universal portability, verified target loading, production-grade encrypted release, enforcement of every tool action, lower token cost, superior security, scale benchmarks or working OpenHands/LNSAT/VUSL connections without corresponding evidence. Native confirmation, Rangoon review and engine authorization remain distinct.

## Delivery sequence

1. Current slice: focused navigation labels/grouping and this synchronized messaging brief. No new executor or connection behavior.
2. Next engineering slice: freeze and accept the isolated Agent Server adapter/test scope; qualify input/configuration readback, confined execution, stable identity, recovery and honest evidence.
3. Next UI slice: expose only qualified adapter operations through a target/run/inspector flow; compare usability with OpenHands alone. Retain a replaceable adapter and one execution owner.
4. Expand only after representative use demonstrates reduced operator work or better detection/recovery/evidence, with actual costs recorded. No savings or market-superiority claim follows from the initial UI pass.
