# Portable workflow definitions

Authority: accepted V1 objective and the owner's node-building request in [intent.md](intent.md). This document is the controller's implementation contract for workflow authoring. [development.md](development.md) remains the only evidence ledger. It does not authorize execution or declare V1 complete.

## Outcome and sequence

Operators build reviewable workflows from named nodes, connect control paths and typed data ports, inspect mistakes at their source, and explicitly save immutable definitions. The current sample Workflows page is not that implementation. Deliver the portable definition/validator first (W1), native saved revisions and recovery next (W2), then a real node editor and all-three-OS qualification (W3). Governed execution is a later independent contract; the definition model carries no approval, credential or run state. Model proposal attribution remains separate unfinished work.

W1 adds `rangoon-workflow`, a pure Rust crate with no filesystem, database, network, clock, process, model or engine dependency. Its useful output is an inspectable typed definition, deterministic structural diagnostics and a content identity for structurally valid definitions. Native callers must later resolve exact capability revisions. A valid graph is not a runnable or authorized graph.

## Version 1 wire contract

The UTF-8 JSON object has fields in serialization order: `schemaVersion` (exactly `rangoon.workflow-definition.v1`), `title`, `nodes`, `controlEdges`, `dataEdges`. Unknown or duplicate object fields, unknown enum variants, trailing data, malformed JSON and invalid UTF-8 are rejected. Whitespace and input object-key order do not affect identity. Array order and every accepted string byte do. No Unicode or newline normalization occurs.

The root title uses the same title rule as node titles below. Each node has `id`, `title`, `operation`, `inputs`, `outputs` in that order. IDs and port names are ASCII identifiers matching `[a-z][a-z0-9_-]{0,47}`. Node IDs are unique across the entire graph; duplicate IDs receive `duplicate_node_id` and prevent ambiguous endpoint/topology calculations. Titles use the existing capability title rule (trimmed, nonempty, at most 160 UTF-8 bytes, no control/line-separator characters). Input and output port names are unique within their respective direction; the same name in opposite directions is allowed. A port has `name`, `dataType`; data types are closed `text`, `json`, `boolean`. Every declared input requires exactly one mapping; an output may fan out. There is no wildcard, implicit coercion, expression language, executable text or dynamic port discovery.

`operation` is a closed internally tagged object using `kind`:

| Kind | Additional fields | Port contract |
| --- | --- | --- |
| `input` | none | No inputs; 1–8 named outputs describing caller-supplied data, not a file/path grant |
| `capability` | `capabilityId`, `revisionId` | 1–8 inputs and 1–8 outputs; exact lowercase 64-hex `capability:`/`revision:` IDs; declared types are unverified against actual skill behavior |
| `check` | `check` | Input `value:text`, output `passed:boolean`; static check declaration only |
| `branch` | none | Input `condition:boolean`, no data outputs; outgoing `true` and `false` control paths |
| `checkpoint` | `prompt` | No data ports; a human checkpoint declaration, never an approval record |
| `output` | none | 1–8 named inputs, no outputs |

The nested check object is tagged by `kind`: `non_empty` has no extra fields; `contains_text` has `needle`, a nonempty string up to 1024 UTF-8 bytes with no NUL. A checkpoint prompt is nonblank, up to 1024 UTF-8 bytes with no NUL. Imported/model-authored title, prompt and needle text remains inert. W1 does not evaluate either check or invoke a capability.

A control edge is `{fromNode, outlet, toNode}`. Outlets are `next`, `true`, `false`. Exactly one input node is the graph entry; at least one output node is required. Input, capability, check and checkpoint nodes have exactly one outgoing `next` edge and no `true`/`false` edges. Branch has exactly one `true` and one `false` edge and no `next` edge. Output has no outgoing control edge. Any other source-kind/outlet combination is invalid even if its endpoint exists. Entry has no incoming control edge. Every other node must be reachable from entry and able to reach an output. Multiple incoming control edges are allowed to join alternative paths; they do not define a parallel join or retry. A branch may send both alternatives to the same target. Duplicate identical edges, self-edges, missing endpoints and cycles are errors. Initial graphs are directed acyclic graphs; loops require a later explicit bounded semantics contract.

A data edge is `{fromNode, fromPort, toNode, toPort}`. Its endpoints must exist; source must name an output port, destination an input port, and types must match exactly. Duplicate edges and multiple producers for one input are errors. The producer must strictly dominate the consumer in the control graph: every entry-to-consumer path passes through the producer, and producer and consumer differ. This forbids unavailable branch-local values being silently mapped into a later joined node. Shared entry values can bypass control steps when dominance holds. Branch results cannot be implicitly merged; later explicit merge semantics will need their own node contract. This is structural availability, not proof a capability actually produces its declared output.

## Bounds and deterministic validation

Reject raw input exceeding 128 KiB before JSON parsing. Require 2–128 nodes (zero/one is a structural `invalid_node_count` diagnostic; exceeding 128 is a decoding/resource error), at most 256 control edges, at most 1024 data edges, and at most eight ports in either direction of each node. Reject excessive collections before graph traversal. Parsing may allocate at most the bounded input representation; validation and identity serialization must not create unbounded intermediates. Maximum JSON container nesting is 32, counting the root object as depth one. A bounded byte scan counts object/array delimiters only outside quoted strings (including escaped quotes/backslashes), rejects deeper input before parsing, and leaves malformed syntax to the strict decoder. Serde JSON recursion protection also remains enabled. Allocation is proportional to the at-most-128-KiB raw representation plus bounded graph/report collections; this is not a claim that total allocation is only 128 KiB. No recursive graph traversal is needed.

Use node array order for stable diagnostics, dependency order and topological tie breaks; inspect control edges and then data edges in their original array order. Within a node, inspect fields in wire order (`id`, `title`, `operation`, `inputs`, `outputs`) and ports in array order. For multiple errors at the same field/location, emit codes in the code-list order below. Root title/count checks precede nodes; control entry/output-count diagnostics precede control-edge checks, which precede per-node cardinality/topology/reachability diagnostics. Data-edge checks precede per-node input-cardinality diagnostics. Node-index order governs every per-node pass. This order governs the first 128 retained diagnostics. Diagnostics contain closed codes and bounded numeric node/edge/port locations, never raw JSON, prompt text, needles or arbitrary error strings. Retain at most 128 diagnostics and set `diagnosticsTruncated` if further errors exist. Truncation never makes a definition valid. Structural errors remain reportable for an editor, rather than dropping the entire otherwise decodable draft. Wire decoding/schema/resource failures have closed error codes and no source echoes.

Validation stages: field/collection/kind checks; node/port identity checks; control endpoints/outlets/cardinality; cycle/topology and entry/output reachability; typed data mappings, exact input cardinality and dominance. When a prior error makes a later calculation ambiguous, skip that dependent calculation while preserving the prior failure. Never index through an unvalidated endpoint. Use bounded iterative graph algorithms. Include only syntactically valid capability/revision pairs in report dependencies and deduplicate them in first node appearance order; invalid reference strings remain only in the decoded inert definition and receive diagnostics. Do not infer a reference exists merely because its ID is well formed.

The public entry point is `inspect_definition(&[u8]) -> Result<DefinitionInspection, WorkflowError>`. An inspection has private fields, read-only getters for the decoded definition and report, and serialization but no deserialization. Report schema is `rangoon.workflow-validation.v1`; fields are `schemaVersion`, `structurallyValid`, `definitionId`, `diagnostics`, `diagnosticsTruncated`, `topologicalOrder`, `dependencies`, `referenceStatus`, `executionStatus`, `authority`. `referenceStatus` is always `unverified`, `executionStatus` always `unavailable`, and `authority` always `none`. Topological order is emitted only for structurally valid graphs; invalid graphs have no definition identity. Report dependencies are references only, not source content, review records or attestations. The wire definition has no supplied identity to trust.

### Report and error wire details

The inspection serializes exactly `{definition, report}` in that order. The decoded definition uses the versioned member order above. `topologicalOrder` is an array of node ID strings, with node-array index as the tie breaker. Dependencies are objects `{capabilityId, revisionId}` in that member order, including only syntactically valid pairs. Invalid graphs use `definitionId: null` and `topologicalOrder: []`. Diagnostic truncation is an error state, never a warning-only success.

A diagnostic serializes fields in order: `code`, `nodeIndex`, `controlEdgeIndex`, `dataEdgeIndex`, `portIndex`. Locations are zero-based integer indices into the submitted arrays or `null` when inapplicable; all five fields are present. Node port diagnostics use `portIndex` with their closed code identifying direction where applicable; operation-level port-shape errors use `portIndex: null`. The code enum serializes to the following closed snake-case values:

`invalid_title`, `invalid_node_count`, `invalid_node_id`, `duplicate_node_id`, `invalid_input_port_name`, `invalid_output_port_name`, `duplicate_input_port`, `duplicate_output_port`, `invalid_operation_ports`, `invalid_reference`, `invalid_check_needle`, `invalid_checkpoint_prompt`, `entry_count`, `output_missing`, `missing_control_endpoint`, `duplicate_control_edge`, `self_control_edge`, `invalid_control_outlet`, `control_cardinality`, `entry_incoming`, `cycle`, `unreachable_node`, `no_output_path`, `missing_data_endpoint`, `missing_output_port`, `missing_input_port`, `duplicate_data_edge`, `self_data_edge`, `type_mismatch`, `input_cardinality`, `data_not_dominating`.

`WorkflowError` is a closed enum whose `code()` and Display output are exactly one of: `input_limit` (raw bytes), `invalid_encoding` (UTF-8), `invalid_json` (syntax, unknown/duplicate fields, variants or wrong field types), `unsupported_schema`, `collection_limit` (maximum collection counts), `depth_limit`, `canonical_limit`, `inspection_limit`, `serialization_failed`. These errors produce no inspection and contain no source text or decoder diagnostics. Remaining well-typed definition faults are the structural diagnostics above. This error/diagnostic distinction permits an editor to retain an incomplete typed graph without treating malformed wire input as a valid draft.

For valid graphs, `definitionId` is `workflow-definition:` plus lowercase SHA-256 over `rangoon.workflow-definition.v1\0`, the unsigned big-endian 64-bit byte length, and compact serialized definition JSON in the field order above. Nested member order is fixed: node `id,title,operation,inputs,outputs`; port `name,dataType`; operation `kind` then the additional fields in the table order (`capabilityId` before `revisionId`); nested check `kind` then `needle` when present; control edge `fromNode,outlet,toNode`; data edge `fromNode,fromPort,toNode,toPort`. Encoding uses compact UTF-8 without a BOM, whitespace or trailing newline. Escape quote/backslash as `\"`/`\\`; use `\b`, `\t`, `\n`, `\f`, `\r` for their control characters and lowercase `\u00xx` for other U+0000–U+001F characters; other characters, including slash and non-ASCII Unicode, remain literal UTF-8. The pinned workspace `serde_json` encoder must match known-byte and independently calculated digest fixtures; changing encoder behavior requires compatibility review. This is a project encoding contract, not a general JSON canonicalization standard. Identity excludes report status, presentation coordinates and future run state. It is content correlation, not authentication, authorization, tamperproof storage or a stable workspace record ID. Expose canonical definition bytes through a fallible bounded method for later immutable storage. This method also permits a decodable, structurally invalid draft to round-trip its definition; it does not assign that draft an identity, validation success or authority. `canonical_limit` means an actual byte-limit failure, not structural invalidity. Limit canonical definition bytes to 128 KiB and serialized inspection to 256 KiB; reject rather than truncate definition text. Hash via existing domain digest helper.

## Later saved workflow and editor contract

W2 must define stable workflow identity, immutable content-addressed revisions, expected-head writes, pinned capability dependency validation, transaction/recovery behavior and compatible backup/restore/deletion together. Saving a valid definition cannot grant execution. Draft handling must allow visible incomplete work without labeling it validated; distinguish an editable draft from a validated revision. Re-resolve dependencies on inspection/save and show stale/missing references rather than silently tracking latest skill versions. These are required follow-on outcomes, not W1 storage behavior. The controller's [workflow record contract](workflow-records.md) defines W2a portable immutable records and the required durable storage/recovery sequence.

W3 preserves the supplied workflow layout: node library, central canvas, inspector, theme artwork and visible graph outcomes. Drag/drop, right-click, visible menus and keyboard operations edit one controller definition, with bounded undo/redo and unsaved-text protection. Draw control edges separately from typed data mappings; show a mapping editor without requiring users to type port IDs. Source/outline/diff views describe the same definition. Branch labels and human checkpoints must stay understandable. Static validation reports links to actual problem nodes and never shows a fabricated successful run. Native/OS and accessible interactive qualification remain mandatory.
