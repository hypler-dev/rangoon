## Historical aspirations that require careful treatment

The assessment conversation proposes a separate knowledge or memory fabric for canonical records, retrieval, graph projections, caches, and context compilation. It names PostgreSQL/pgvector, Qdrant, Valkey/Redis, Mem0 and Cognee/Graphiti as possible external systems. These are candidate dependencies, not integrations or a direction to build a distributed database. Memory operations such as ingest/promote/invalidate/delete need their own action and derived-data revocation contracts. Do not add them to desktop v0 merely because a previous brainstorming answer listed them.

The older public-core/downstream split permits commercial management features. Current user direction puts the first Rangoon app in the free open-source base. This is a product packaging change to reconcile through review, not evidence that a license already exists. Underlying LNSAT authority contracts and essential security fixes stay open and common across editions.

## Deliberate first-release exclusions

Multi-tenant cloud, arbitrary code plugins, automatic production deployment, enterprise connector breadth, a full agent framework, a new vector database, mobile background agents, and compliance certification are excluded from the first desktop management release. Their requirements are retained above for future review. This keeps the ambition while making the initial product useful and testable.
