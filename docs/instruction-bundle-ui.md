# Native instruction-bundle export and inspection

Authority: accepted V1 continuation in [intent.md](intent.md). This implements the native stage of [instruction-bundle.md](instruction-bundle.md), preserving its frozen byte format, file limits and custody boundaries. The primary controller owns native integration, DTOs, validation and publication. Evidence belongs in [development.md](development.md). This is not full R4/R5 or V1 completion.

## Outcome and ownership

From Compile, export the exact reviewed candidate to a newly selected plaintext `.rangoon-instructions` file. Independently inspect a selected external bundle without importing, reviewing or executing it. Preserve saved Compile reports, Skills/composition drafts and source-analysis sessions. External evidence never enables saved-workspace export. The controller owns native code/bindings; separate workers own the Compile model/validation tests and the view/style tests. No schema migration, provider, network, engine, installation, encryption or dependency change is required.

## Closed native commands

Both commands use raw UTF-8 JSON, bounded to 4,096 bytes before deserialization, with unknown/duplicate/missing/type errors rejected. Tauri has already received the transport buffer. Register only for the existing local main window and hold the existing operation guard through picker and blocking work.

`export_instruction_bundle` accepts exactly `schemaVersion: rangoon.instruction-bundle-export-request.v1`, `capabilityId`, `revisionId`, `profile` (the two frozen profiles), and `expectedCandidateId`. IDs must have their existing lowercase 64-hex forms. No renderer path, source, manifest, review flag or file bytes are accepted. Use a neutral `Rangoon.rangoon-instructions` save name and an explicit plaintext picker title. After selection, open the workspace, resolve the exact selected revision, compile again, and require its candidate ID to equal the expected ID. Missing records, noncandidate output and changed review evidence fail before creation with `instruction_candidate_changed`. Other store failures retain fixed public diagnostics. Encode and write the same fresh compilation object with the existing exclusive host helper. Historical revisions are valid selections; no head substitution or live database lease is implied.

Successful export is exactly `{outcome: exported, schemaVersion: rangoon.instruction-bundle-export.v1, bundleId, candidateId, sha256, byteLength, authority: none}`. The digest covers the whole file. Success follows completion of write and file sync; it does not establish future integrity, directory durability or authentication. No path is returned.

`inspect_instruction_bundle` accepts only `schemaVersion: rangoon.instruction-bundle-inspect-request.v1`. After a native open picker, read using the bounded regular-file helper and invoke the pure verifier. Never open or create the workspace. Success is exactly `{outcome: inspected, schemaVersion: rangoon.instruction-bundle-file.v1, inspection, candidateManifestJson}`. `inspection` is the existing `rangoon.instruction-bundle-inspection.v1` record; the manifest string comes from its reconstructed candidate's canonical serializer.

Cancellation is exactly `{outcome: cancelled}` and performs no further work. Failure is exactly `{outcome: failed, error: {code, message}, outputState}`. `outputState` is `not_created` when this attempt did not create output; export write/sync failures or an unexpected blocking-task join failure use `uncertain`. Inspection failures always use `not_created`. Invalid requests use `instruction_bundle_request_invalid`; missing native window/path conversion uses `instruction_bundle_unavailable`; busy uses `workspace_busy`. Fixed messages never echo paths, OS/parser errors or source. An unconfirmed transport response is uncertain for export, regardless of any retained previous receipt. No automatic cleanup, overwrite or retry occurs.

## Controller and evidence verification

Extend the existing Compile controller with independent `bundleExport` and `externalBundle` state. `bundleExport` has `status` (`idle`, `pending`, `cancelled`, `exported`, `failed`, `uncertain`), `receipt` and `error`; `externalBundle` has `status` (`idle`, `pending`, `cancelled`, `inspected`, `failed`), `report`, `previous` and `error`; `report` and `previous` are validated inspection/manifest objects or `null`, with older evidence moved to `previous` after cancellation/failure. Both share the controller's `pending` gate (`export` or `inspect-bundle`) and the binding's global native-operation gate. File-operation results need an independent epoch: a known workspace invalidation can stale saved evidence while a file picker is active, but must not silently discard an export outcome or external inspection. Invalidation preserves the pending file operation; its eventual receipt cannot clear saved-report staleness. Changes to saved selection/profile clear its export receipt, while external inspection remains independent.

`exportBundle()` requires a native bridge, no pending operation, no refresh requirement, a nonstale retained report with candidate readiness and exact candidate ID. It sends raw JSON from the retained selection/profile/candidate, never rendered content. Before accepting success, reconstruct the deterministic bundle framing from the retained canonical manifest and exact artifact text, then compare candidate ID, bundle ID, whole-file digest, byte length, schema and authority. SHA-256 availability is required. Bad/missing/uncorrelated success or transport failure is uncertain. Known no-output failures preserve the candidate except `instruction_candidate_changed`, which requires refresh/recompile. Cancellation preserves the candidate and no longer presents an older receipt as the current attempt's result.

`inspectBundle()` works even with an empty/unavailable workspace. Validate the closed success envelope, bounded candidate report, manifest and all fixed profile/readiness/authority values. Recompute artifact digest/length, canonical manifest hash, compilation/candidate identities, exact bundle bytes, whole-file digest, length and bundle ID. Validate ordinary revision identity and composition-reference shape without inventing missing provenance graphs or creation times. Reject unavailable hashing, unknown fields, inconsistent data and overlimits. These renderer consistency checks are not authentication or a replacement for native validation. External content stays escaped inert text; no Markdown/HTML execution. Failed/cancelled inspection retains an older report only under a visible previous-inspection label; it never changes saved selection, review or exportability.

Use fixed frontend error copy for these file actions; unknown native errors must not echo untrusted messages. Keep the pre-existing Compile behavior and tests intact. Direct controller calls cannot bypass pending/stale gates. No browser upload/download fallback, provider or automatic file action is added.

## Interface and accessibility

Keep the existing three-column Compile workbench. Add a portable-action card in the evidence rail showing plaintext disclosure and the expected candidate ID. Export is a separate explicit button; the native save picker is the operator confirmation, with no extra modal. Explain disabled states (compile first, review required/blocked, refresh required, busy or native unavailable). Show exact export receipt facts, qualified as completion of this write/sync only. Distinguish known no-output failure from uncertain output and require a new name for retry after uncertainty.

Add a fourth `External bundle` tab, available without saved skills or a compilation. Its empty state explains selected-file inspection. It contains a native inspection launcher, independent pending/error state, external-file evidence label, internal-consistency/authority limits, profile/revision/provenance facts, manifest and escaped text. An action in the portable card can launch the same inspection. Never offer export, import, review or Skills navigation from external evidence.

Preserve route-entry focus and existing Compile success focus. File-action cancellation/failure returns focus to its launcher (or Refresh when candidate invalidation disables Export); successful export focuses the receipt heading, successful inspection selects the external tab and focuses its heading. Four-tab roving ArrowLeft/Right/Home/End navigation, polite pending/success announcements, visible failure alerts, focus styles, wrapped IDs and scrollable text remain required. Retain dark/light, reduced-motion and narrow layouts; no document overflow at 320/768/1440 widths.

## Acceptance and qualification

Native tests cover closed raw requests, picker cancellation without opening a store, post-picker resolution, stale/missing/unreviewed/wrong-owner selection, historical selection, exact bytes/receipt correlation, no overwrite, uncertain writer outcome and unchanged database/session state. Inspection tests cover empty workspace, invalid bundle, cancellation, exact canonical response and no storage mutation. Permissions must expose only the two new local-main commands.

Controller/view tests cover direct gates, cancellation/known failure/uncertain/lost/mismatched responses, independent invalidation epochs, historical candidates, external metadata/content corruption, absent hashing, source escaping and preserved prior evidence/drafts. Independent compiler/bundle fixtures must remain unchanged. Named native/Node/format/Clippy/docs checks and fresh independent source/UI reviews precede publication. Render dark/light desktop/tablet/narrow and keyboard/focus states with explicit synthetic fixtures; actual native GUI/IPC proof remains separately recorded. All-three-OS GUI, target-loader conformance, remaining R3 GUI, release/installer, license and V1 gates remain open until proven.
