On success the app opens the source workbench and focuses its title. Existing native sections enable section-based skill creation; the existing Skills source/title state is reused. On failure the file inspection and prior analysis remain available. Busy, mismatched, removed and unavailable results have bounded distinct diagnostics and retry guidance. Temporary selected-file results cannot use this saved-reference action; the UI explains how to open a saved record or explicitly select/save through Import. No silently saved batch, arbitrary filesystem path or renderer-supplied original is accepted.

Duplicate opens and pending actions are refused. Workspace purge invalidates both controllers and late callbacks; deleting a source during its pending open marks that exact request removed and rejects its eventual result after callback drain. User navigation invalidates automatic route completion even if the user returns to Agent files before the result arrives. The app must not force a stale route/focus to Import. Existing skill drafts, source-specific creation titles, composition, persistence, export and authority boundaries remain.

The [development receipt](development.md#fh-1-saved-file-source-workbench-handoff--october-27-2026) separates real renderer/source evidence from native current-artifact GUI qualification. This is an application handoff over an existing native read/selection operation, not an implemented remote connector, source-file writer or bulk import/save.
