# Complete native workspace controls

Authority: accepted workflow authoring sequence in [intent.md](intent.md). This W2c-1 specification adopts the complete [workflow workspace contract](workflow-workspace.md) in native data controls before native workflow creation is registered. Acceptance and publication receipts belong only in [development.md](development.md). It builds on the published W2b store lifecycle; it does not introduce another storage format.

## Outcome and boundary

The Data route shows every saved source, skill and workflow owner, with separate capability and workflow revision counts. Backup includes complete immutable history. Restore can add a workflow-only archive. Deletion previews show both skill and workflow blockers, including references from historical draft revisions. Workflow deletion removes only its owner and history; original input files and dependent inputs are preserved. Local storage and archives remain unencrypted; logical deletion is not secure erasure. Structural validity and validated save intent are observations, not review, execution, authentication or LNSAT authority.

This slice registers no workflow creation/save/open commands and adds no workflow editor or execution. A selected V3 archive may legitimately introduce schema 4 through the existing explicit restore flow after full preview and confirmation. Existing version-aware source, skill, composition and compilation APIs already preserve complete workflow state. Never route this through a legacy record projection.

## Native adoption and custody

Keep the six existing data-control command names and their current selector arguments, but adopt only the explicit v2 DTOs as one coordinated native/frontend source change:

- `get_workspace_data` calls `workflow_data` and returns `Loaded { workspace: WorkflowWorkspaceData }`.
- `export_workspace_backup` calls `export_workflow_backup`; existing native picker, exclusive destination creation, fixed errors and plaintext warning remain.
- `prepare_workspace_restore` uses `WorkspaceBackup::decode` and `prepare_workflow_restore`; return `RestoreReady { plan: WorkflowRestorePlan }` and retain the exact opaque backup and private plan.
- `restore_workspace_backup(backupId, expectedStateId)` selects only the retained backup/plan, calls `restore_workflow_backup`, and returns `Restored { plan }` only after the store confirms success. The returned complete workspace is not substituted for the exact inspected plan in this receipt.
- `inspect_workspace_deletion(kind, id)` calls `inspect_workflow_deletion` and retains its private `WorkflowDeletionPlan`.
- `delete_workspace_record(kind, id, expectedStateId)` selects only that retained plan, calls `delete_workflow_record`, and returns `Deleted { kind, id }` only after confirmed success.

Native command kind is a closed deserializable adapter with lowercase `source`, `capability`, `workflow`, mapped to the store's Serialize-only `WorkflowRecordKind`. Do not add Deserialize or public constructors to private store plans. Renderer supplies selectors, never plan fields, SQL, archive bytes or file paths. Existing main-window-only local permission list and shared mutation/picker busy guard remain. Reads remain noncreating and report unavailable/corrupt state rather than fabricated empty success.

Each session retains at most one candidate. A successfully staged new preview replaces the prior one. Picker cancellation or failed preparation preserves the prior native candidate. An explicit cancellation keeps the previous renderer preview usable. A failed or malformed preparation response marks that renderer preview stale: the bridge may have lost a response after staging a replacement, so retention is not permission to retry an uncertain preview. Matching confirmation atomically takes the retained candidate before invoking storage; success, store refusal, callback failure or uncertain return all consume that attempt. Mismatched selectors do not consume the valid candidate. Repeated confirmation needs a fresh preview; never retry a write automatically. This tightens the preceding sessions, which consumed only after success, and must be covered directly by tests. The exact full plan and current state are revalidated by the store transaction; session custody is not authentication of a human decision.

## Renderer contract and experience

The production controller accepts only `rangoon.workspace-data.v2`, `rangoon.restore-plan.v2`, and `rangoon.deletion-plan.v2`, with the exact closed fields from W2b. V1 fixtures remain tests of rejection, not a fallback that can omit workflows. Validate all bounds, IDs, sanitized labels, timestamps, booleans, closed intent values, unique owners/dependency lists, count/history relationships and source-origin membership before rendering. Workflow summaries use exact W2b fields; unresolved references are at most 128 per head. A `validated` summary must have `structurallyValid:true` and `unresolvedReferences:0`; reject either contradiction. Sum owner revision counts independently for skills and workflows. Counts bound workflow owners at 128 and workflow revisions at 1024, with 1–32 revisions per owner.

Restore totals include `keptWorkflows`; workflow additions with zero source/skill additions are actionable. Treat no additions as all nine add counts zero. Verified restore receipts must match every issued field/count, including workflow fields, before mutation callbacks. Deletion accepts three kinds, uses `label`, `capabilityDependencies`, and `workflowDependencies`; either dependency list blocks confirmation. Removal counts must match the selected kind: source removes one source only; skill removes one owner and 1–32 capability revisions plus applicable composition records, never workflows; workflow removes one workflow and 1–32 workflow revisions only. Reject unknown fields and impossible counts rather than filling defaults.

Keep Data's established hero, grouped shell, compact panels, theme tokens, modal confirmation and keyboard focus behavior. Add a third saved-workflow panel with display label, draft/validated-intent wording, structural result, unresolved reference count and revision count. It offers Inspect and explicit Delete actions; it must not suggest an editor is ready. Metrics and recovery previews label capability and workflow revisions separately. Export warning includes workflow history, recipes and local reviews. Blocked deletion lists both kinds of dependents and states that no record is removed while blockers remain. Restore explains that existing heads/histories are retained; incompatible incoming history is refused. Escape all imported labels and IDs as text.

Preserve active analysis and unrelated drafts. In `analyze.mjs`, only source deletion may call `noteSnapshotDeleted`; workflow deletion must not be misclassified as source deletion. Keep existing skill-specific draft warning/clearing. A later W3 editor must add its own explicit draft preservation/deletion handling; none exists here. Modal review content scrolls separately from its fixed action footer, so initial Cancel focus does not hide the title or scroll past the initial review text on narrow screens. No new animation or artwork changes are required.

## Ownership, validation and rollback

Root owns native privacy/custody/integration and documentation. Exact native files: `apps/desktop/src/data_controls.rs`, `apps/desktop/Cargo.toml` (workflow fixture development dependency only), and `apps/desktop/Cargo.lock`. Bounded frontend writer owns `preview/workspace-model.mjs`, `preview/workspace-view.mjs`, `preview/workspace.css` only if needed, `preview/analyze.mjs` only for deletion-kind routing, and `tests/workspace-model.test.mjs`. The shared validator is also consumed by `preview/composition-contract.mjs`; the same frontend writer owns only the v2 inventory fixture conversion in `tests/composition-model.test.mjs`, preserving composition behavior. Root also owns the final bounded modal scrolling, impact grammar, metric grid and authority-note corrections plus their view assertions after the frontend worker completes. Root owns this specification, README, continuation, workflow-storage cross-link and development ledger. No store schema/production changes, CI changes or parent marketing edits are needed.

Required checks: native formatting, locked tests, warnings-denied all-target Clippy and build; `npm run build:check`; authored-artifact and whitespace checks. Native session tests use actual opaque plans from disposable workspaces, including schema-4 histories, exact selector rejection, replacement, one-attempt failure/uncertainty handling and compatibility with V1/V2 archives. Renderer tests cover strict v2 shapes, malformed/unknown/v1 rejection, workflow-only restore, receipt comparison, historical workflow blockers, workflow deletion arguments/callbacks, escaping and separate counts. Render light/dark 320/768/1440 views for populated inventory, workflow-only restore, blocked skill deletion and workflow deletion; verify overflow, modal focus, Escape and pending guards. Fresh independent read-only source/UI review is required.

Native command/session source tests and synthetic rendered checks are distinct from interactive native picker/IPC proof. Record any unqualified macOS/Windows/Linux GUI cases explicitly. Source CI does not qualify released desktops or V1. Rollback is source reversion before publication; after any schema-4 restore, old binaries may refuse the richer workspace. Do not replace, downgrade or discard that workspace. Preserve complete backup access through this version-aware source.

External gates remain closed: provider/private-source transfer, existing credentials, LNSAT activation, arbitrary execution, installers/releases, deployment, license adoption and grant submission. Each main publication includes a substantive README update.
