## Outcome and boundaries

Replace the functional workbench's missing Workflows area with a real local definition editor. Preserve the original Workflows screenshot hierarchy: grouped navigation, compact themed hero, workflow/node library, central graph and right inspector. The separate historical design preview stays synthetic. This is inert authoring, static inspection and explicit local revision storage; no runner, provider, engine, approval, policy activation or persistent automatic transfer is added.

Use Input, Capability, Check, Branch, Checkpoint and Output node kinds from the existing closed domain. Control connections and typed data mappings are separate records. Layout positions are presentation only. A capability node pins an exact saved local capability/revision through the existing read APIs; its content review status is separate from workflow structure. Empty or structurally invalid but decodable definitions can be saved as `draft`; `validated` requires native structural validity and resolved exact local pins. Neither intent establishes review, execution or authority.

## Controller and native lifecycle

One controller owns the local definition, layout, native draft identity/parent, selection, viewport, field edit buffer, undo/redo, selected tab, saved history and inspected candidate. Keep application-native identities opaque; do not generate workflow/revision/store-state/preview identities in JavaScript. Renderer node IDs are local graph labels only. No workflow source/content is persisted in browser storage or transmitted.

Use the six published commands and raw UTF-8 JSON requests exactly as specified by native custody. Read capability inventories/details through existing `list_capabilities` and `open_capability` commands. Reject unknown/missing fields, enums, out-of-bound arrays/text/coordinates, malformed IDs and inconsistent relationships in native responses before using them. Definition checks enforce the decodable closed shape/resource boundary, not a replacement structural validator; incomplete domain data must remain inspectable as Draft. Native report supplies structural conclusions. Renderer validation is defensive UI behavior, never authentication or tamperproof evidence.

1. Refresh inventory without clearing current work. Failure retains prior inventory and draft. No native bridge means visible unavailable state; do not substitute fixtures in the production editor.
2. Open an exact current or historical revision read-only. Opening never begins a draft, changes a head or silently discards edits. History comparison reads two exact revisions and reports structural/layout changes, without mutation. Append starts explicitly from the selected current head through `begin_workflow_draft`; a head conflict requires explicit refresh/reconciliation. New draft uses native-issued identity and an empty decodable local definition/layout. Failed beginning preserves previous draft; uncertain replacement invalidates the old preview without erasing renderer edits.
3. Add/edit/remove/reorder nodes and ports, add/remove control/data connections and move nodes through one action controller. A bounded local undo/redo history (at most 50 actions) includes structure and positions, never native writes. Remap layout `nodeIndex` atomically with insertion/removal/reordering. Node removal confirms removal of incident connections; no automatic persistent workflow deletion is introduced. Invalid endpoint/outlet/type or occupied input selection explains its refusal and never silently replaces a mapping. Native inspection remains authoritative for cardinality, dominance, reachability and structural validity.
4. Pending field text remains visible across rerenders/errors. Apply or Cancel resolves that buffer before structural changes, inspection, open/new/append or comparison. Opening/replacing a dirty draft asks Keep editing or Discard local changes; only explicit discard clears the matching native session. Route navigation may retain the in-memory editor without clearing it; full window close warns when local edits remain, without claiming durable recovery.
5. Draft inspection uses the exact current authored definition/layout and native draft handle. Validated inspection is available after a fresh native draft report establishes structural validity and zero unresolved references; it still uses a new native validated inspection and may refuse due to changed dependencies. Successful inspection binds returned draft/workflow/parent/intent and exact canonical definition/layout to the inspected local edit generation. Edits, undo/redo, layout changes and external workspace writes stale the candidate and clear acknowledgment. Selection/tab/viewport changes do not alter persisted bytes.
6. Confirmation requires explicit acknowledgment of the exact candidate. Capture and clear the usable preview before dispatching the matching native commit. Accept success only if strict receipt identity, parent, intent, exact canonical definition/layout, current head and structural observations match the inspected candidate. Fresh dependency statuses may differ on the native exact-current-head no-op; counts obey the native contract. Refusal, malformed response, callback failure or uncertainty preserves draft/text/layout/history and requires fresh inspection. Never retry writes automatically or silently rebase. Saved receipt is retained even if inventory refresh fails. Continue editing after a save requires explicit new append session at its returned current head; do not reuse the old parent.

Serialize mutations and native calls per controller. Pending operations lock local mutation; request/edit/session generations prevent obsolete responses from replacing a newer draft. Shared workbench workspace mutations invalidate workflow candidates and capability selections when needed, including Data restore/deletion, capability writes and composition commits. Workflow commit invalidates other content compilation/composition/model observations through the existing shared bridge. Lost or malformed bridge replies are uncertainty, not fabricated failure/success evidence.

## Workbench interactions

Hero: Workflows, “Build reviewable local definitions.” Actions New workflow and Refresh library. No sample totals, Run/Test/Deploy actions, policy-compliance percentage or approvals. Library shows actual saved workflows and the six node types with visible Add buttons and draggable cards. Exact capability/revision selection remains in the inspector.

Canvas node cards expose title, kind, inputs, outputs and separate control outlets. Solid directed control edges label `next`, `true` or `false`; dashed directed data edges label `text`, `json` or `boolean`. Node drag commits one bounded layout action at pointer release. Drag a library type into the canvas to add a node. Dragging an outlet/output to a compatible endpoint follows the same action used by visible keyboard connection controls. Invalid targets leave the graph unchanged and explain the problem. Right-click, visible Actions and Menu/Shift+F10 open the same contextual menu; menus support arrows/Home/End, Escape/outside dismissal and focus return. Native text-field context menus remain intact.

Canvas, Outline, Definition and Diff tabs share controller state. Outline supplies complete labeled node/edge operations without relying on wires, including selected-node move/reorder and connection forms. Definition displays closed authored JSON as text; saved/candidate JSON is explicitly identified as native canonical data. Diff compares selected exact saved revisions, is read-only and does not imply authorization or semantic equivalence. Inspector exposes pending field edits, operation/port configuration, exact pins, linked native diagnostics, history and candidate details. Compact status shows Draft, Validated candidate or Saved revision, structural issue/reference counts and one-attempt save state. Do not flood the primary workflow with raw enum/ID text; retain technical details in expandable inspector records.

## Presentation and accessibility

At 1440 pixels use a three-panel layout with approximately 240px library and 320px inspector. At 768 pixels library stacks above and inspector below. At 320 pixels Outline is a usable primary representation; neither page nor controls overflow horizontally. Preserve orange Foldline identity, existing light/dark assets and decorative sidebar mascot. Workflows hero uses fixed route art; art cannot move controls or signal readiness. No new bitmap generation is required for this packet.

Use semantic headings, labels, named buttons, live polite status, visible keyboard focus and at least 36px icon-only targets. Data/control distinction has text and line patterns beyond color. Reduced motion disables decorative movement and automatic pan/scroll. Forced colors retains borders, focus, node/edge labels and controls while hiding decorative hero art. Restore text selection, focus and scroll after rerenders; viewport changes do not create saved layout revisions.

## Ownership, validation and publication

The renderer module interface is explicit so disjoint workers can integrate without shared-file edits. `createWorkflowController({bridge,onChange,onSaved})` returns `getState`, `load`, `open(workflowId,revisionId=null)`, `beginNew`, `beginAppend`, `clear(confirmed)`, `compare(leftRevisionId,rightRevisionId)`, `select(selection)`, `setTab(tab)`, `setViewport(patch)`, `editFields(target,patch)`, `applyFields`, `cancelFields`, `addNode(kind,position)`, `removeNode(index,confirmed)`, `reorderNode(index,delta)`, `moveNode(index,x,y)`, `connectControl(fromIndex,outlet,toIndex)`, `connectData(fromIndex,fromPort,toIndex,toPort)`, `removeEdge(kind,index)`, `chooseCapability(capabilityId)`, `pinCapability(nodeIndex,capabilityId,revisionId)`, `undo`, `redo`, `inspect(intent)`, `acknowledge(value)`, `commit` and `invalidate(message)`. Failed/blocked actions return false or a closed failure state; success returns true or a confirmed native result. Root/view must never inspect private native buffers. Opening/new/append while dirty is blocked; the view offers explicit confirmed `clear(true)` before retrying the requested navigation. In-app route navigation retains the controller instead of clearing it.

`getState()` returns a cloned snapshot with `bridgeAvailable`, `status`, `pending`, `message`, `workflows`, `capabilities`, `capabilityDetail`, `opened`, `comparison`, `session`, `definition`, `layout`, `dirty`, `candidate`, `acknowledged`, `receipt`, `tab`, `selection`, `viewport`, `fieldEdit`, `canUndo` and `canRedo`. Session contains native `draftId`, `workflowId` and `parentRevisionId`; candidate is the strictly schema-validated native SaveReady envelope, for either draft or validated intent, with the captured edit generation. Selection is null or `{kind:"node"|"control"|"data",index}`. Field target is `{kind:"workflow"}` or `{kind:"node",index}`; pending field edit retains its target and merged patch. Definition/layout may be null before open/new. Comparison contains the two exact read-only details and a bounded structural/layout change summary. View binds this public interface through `bindWorkflowView(root,controller)` returning `render` and `dispose`; pure `renderWorkflowView(state)` supports source tests and unavailable rendering. Numeric controller limits and field meanings remain those of the native/domain contracts above.

Root owns architecture/integration, docs and publication. A bounded native GPT worker owns only `preview/workflow-contract.mjs`, `preview/workflow-model.mjs` and `tests/workflow-model.test.mjs`. A second bounded native GPT worker owns only `preview/workflow-view.mjs`, `preview/workflow.css` and `tests/workflow-view.test.mjs`. Neither writer edits the other's paths. Root owns integration in `preview/analyze.mjs`/`preview/analyze.html`, `preview/workbench-shell.css`, `package.json`, `docs/vision-contract.json`, this contract, README, continuation and canonical ledger. Add a narrowly required asset/vision validator path only after recording why. Native/domain/store/schema/CI/parent marketing paths are out of this frontend packet. Workers receive only explicit secret-free source snapshots and contract; no credentials, private imports or broad session history.
