# Fixed-origin cloud model adapter

Authority: the accepted model-assistance continuation in [intent.md](intent.md), refined by [model-assistance.md](model-assistance.md). This implementation contract covers the portable cloud transport library. The [portable cloud session](model-cloud-session.md) adds saved-record and single-use request custody. The native credential store and consent workbench must be integrated separately before the application can send cloud requests. Evidence belongs in [development.md](development.md).

## Request ownership

`rangoon-model-cloud` implements one explicit OpenAI Responses request. Construction and profile parsing have no network, OS-store, environment-credential or filesystem behavior. The only production destination is `https://api.openai.com:443/v1/responses`, using HTTP/1.1 over certificate-verified TLS with the fixed DNS name `api.openai.com`. No configurable origin, proxy, redirects, retries, automatic discovery, tools, server conversation, background mode or remote fallback exists. A library call does not establish operator consent.

A closed profile request contains `schemaVersion: rangoon.cloud-profile-request.v1`, `profileId` (1–64 ASCII alphanumeric/underscore/dot/hyphen), `model` (1–128 ASCII alphanumeric/underscore/dot/hyphen, starting alphanumeric), and `maxOutputTokens` (1–32,768). The raw request is at most 1,024 bytes. Model availability and task compatibility remain unverified until separately qualified; aliases may resolve to a different provider-reported model. Canonical profile serialization includes adapter `openai-responses.v1` and the fixed origin.

Preparation takes a matching immutable context pack and a 64-character lowercase-hex OS credential revision. The final JSON body contains model, fixed instructions demanding the pack's JSON proposal, input as the exact pack body string, `store: false`, `stream: false`, `background: false`, `truncation: disabled`, `tools: []`, `tool_choice: none`, `max_output_tokens`, and `text.format.type: json_object`. It never sends a credential revision in the body. Native validation remains mandatory; JSON mode is not schema enforcement. No sampling/effort option is silently added or model substituted.

The final body is capped at 262,144 bytes while serializing. An immutable binding includes schema `rangoon.cloud-request.v1`, adapter, profile digest, fixed origin/method/path, pack ID, credential revision, body SHA-256 and byte length. Request ID is SHA-256 of the domain `rangoon.cloud-request.v1\0`, big-endian u64 binding length, and canonical binding JSON. Preparation exposes the exact body and nonsecret binding; hashes are correlation, not authentication. The native gate must retain this object, resolve full saved inputs, recheck freshness and the exact stored envelope/revision, and collect isolated payload review plus final OS consent before calling transport.

## Credential and transport boundaries

An opaque, non-Debug, non-Serialize, zeroizing credential owns 1–2,048 ASCII graphic bytes and its 64-lowercase-hex revision. The client refuses a revision mismatch before any connection. This library accepts explicitly supplied material only; it does not read the OS slot or enforce native consent. Native integration must supply the validated current envelope under the existing custody lease and prevent concurrent in-process save/remove through dispatch. Same-user out-of-process replacement and credential revocation cannot recall bytes already dispatched.

Use explicit rustls ring cryptography and bundled WebPKI public roots. Do not load custom/system roots, SSL environment variables or disable verification. System DNS resolves only the fixed host. Resolve under a 10-second connection deadline; reject the entire answer when empty, more than 16 addresses, or containing a non-public address. Only the first validated address is dialed; no address retry. The production classifier freezes these IPv4 denials: `0/8`, `10/8`, `100.64/10`, `127/8`, `169.254/16`, `172.16/12`, `192.0.0/24`, `192.0.2/24`, `192.88.99/24`, `192.168/16`, `198.18/15`, `198.51.100/24`, `203.0.113/24`, and `224/3`. IPv6 accepts only `2000::/3`, excluding `2001::/23`, `2001:db8::/32`, `2002::/16`, and `3fff::/20`. This also rejects mapped IPv4, NAT64, discard-only, loopback, unspecified, unique-local, link-local and multicast IPv6. This is a conservative versioned classifier, not a dynamic IANA registry or an assertion that every accepted allocation is reachable. Test-only injection can dial disposable loopback TLS fixtures with a synthetic CA; it is unavailable in production/public API.

One process-wide in-flight operation, one shared 10-second deadline covering DNS, TCP and TLS together (inside the 120-second total request deadline), response HTTP header count maximum 64 and parser buffer maximum 32 KiB, response body maximum 1 MiB, and no decompression. Request/response driver futures share the caller's stack lifetime; cancellation/timeout drops the socket and driver without a detached task. Authorization is created only after TLS verification, marked sensitive in the HTTP header, and never included in receipts/errors. Library/HTTP/TLS internal buffer erasure is not guaranteed.

Accept only HTTP 200 with one application/json content type (optional UTF-8 charset), absent or identity content encoding, bounded declared and received length, and no trailers. Redirects and non-200 errors return closed codes without body text. System DNS work may finish after the caller stops waiting; no credential or source is sent through DNS, and no HTTP task is detached. No response header chooses another destination or triggers retry. Library failures use the closed `Diagnostic` enum; `receipt()` serializes `{schemaVersion: rangoon.cloud-diagnostic.v1, adapter: openai-responses.v1, code, authority: none}`. Codes are `invalid_profile`, `profile_mismatch`, `invalid_credential`, `credential_changed`, `request_over_budget`, `busy`, `cancelled`, `timed_out`, `connection_failed` (DNS/TCP), `address_rejected`, `tls_rejected`, `redirect_rejected`, `remote_rejected`, `response_too_large`, `response_invalid`, `response_incomplete`, `response_refused`, and `proposal_invalid`. No raw body/header, submitted material or library error is serialized in any failure. The native layer will supply its own lifecycle wrapper; these are library diagnostics, not dispatch receipts. Cancellation/timeout/connection loss does not prove no transfer, no provider processing, or zero cost.

## Response interpretation

Preflight UTF-8 JSON before materialization: raw ≤1 MiB, nesting ≤16, object keys ≤64 and 128 bytes each, array items ≤512, values ≤8,192, decoded strings ≤262,144 bytes, duplicate decoded keys rejected. Number lexemes are capped at 128 bytes and must be finite JSON numbers. Unknown top-level provider metadata is bounded and ignored; it never enters application receipts or authority. The application-owned proposal schema remains closed.

Require `object: response`, a bounded `resp_` ID, a bounded printable observed model, `status: completed`, explicit null `error` and `incomplete_details`, and `output` containing exactly one completed assistant message. Optional reasoning items are inert and discarded; only their `id`, `type`, empty `summary`, and optional completed status are accepted. Reject tools, actions, encrypted reasoning, refusal, annotations, multiple messages/text parts, or any other output item. The message requires a printable `msg_` ID up to 128 bytes. The message contains exactly one `output_text` part with empty annotations and optional empty logprobs; text ≤128 KiB. The text must validate against the retained pack through `rangoon-model-assistance`. Never interpret top-level `output_text` as authoritative SDK output.

Optional/null usage stays unknown. If present, nonnegative integer input/output/total tokens must add without overflow, reported output must fit the selected cap, cached or cache-write tokens cannot exceed input, and reasoning tokens cannot exceed output. Usage decodes nested `input_tokens_details.cached_tokens` and optional `cache_write_tokens`, plus `output_tokens_details.reasoning_tokens`, into camelCase receipt fields. All usage/model/response ID observations remain provider-reported. The locally bound completion contains request/profile/pack IDs, SHA-256 of exact received HTTP response body bytes before JSON decoding (excluding HTTP framing/headers), observed model/ID, validated proposals, unknown cost/region/retention, and `authority: none`.

## Qualification and next integration

Required tests: exact profile/request vectors and changed-revision binding; raw/final byte caps; invalid profiles; response duplicate keys, depth/count/Unicode/number limits; refusal/tool/incomplete/forged-citation rejection; trusted synthetic TLS success with exact body/auth; wrong name/untrusted certificate rejection before HTTP; production-address rejection for IPv4/IPv6; redirect/non-200/compression/oversize/truncated response; cancellation/timeout socket closure; busy guard release; no retry; a child test process with HTTP_PROXY/HTTPS_PROXY/ALL_PROXY and lowercase variants pointed at a sentinel proxy must still send exact origin-form HTTPS traffic directly to the TLS fixture, with zero proxy connections. Environment mutation must not race other tests. Ordinary tests use fake credentials and disposable local servers only.

Next native integration must expose explicit configure/prepare/send/cancel and a source-free connection check with its own credential-transfer disclosure/consent, fixed review window, freshness and credential revision gates. No cloud workbench, real provider compatibility, all-three-OS runtime support, paid/private transfer, Zero Data Retention, encrypted workspace or V1 completion claim follows from this library.

Official contract references (read October 6, 2026): [Responses text generation](https://developers.openai.com/api/docs/guides/text), [JSON mode and incomplete/refusal handling](https://developers.openai.com/api/docs/guides/structured-outputs#json-mode), and [data controls](https://developers.openai.com/api/docs/guides/your-data). `store: false` requests no stored response application state; it does not establish Zero Data Retention, account eligibility, absence of abuse-monitoring retention or prompt-cache storage. Provider/account/model policies require separate qualification. The endpoint-only OpenAPI tool returned unresolved component references; it is not recorded as a complete schema source. Its `x-oaiMeta` text-input response example was inspected to verify the message and nested usage wire shape, including `cache_write_tokens`.
