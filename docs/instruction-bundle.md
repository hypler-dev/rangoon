# Portable instruction bundles

Authority: the accepted V1 lifecycle in [intent.md](intent.md). This contract extends [instruction compilation](compilation.md) and [native inspection](compilation-ui.md); validation and publication receipts belong in [development.md](development.md). The primary controller owns architecture, integration and publication. This is a bounded R4/R5 increment, not completion of either stage or V1.

## Outcome and delivery stages

An operator exports the exact locally reviewed revision and profile they inspected as a single portable `.rangoon-instructions` file. It preserves original instruction bytes and the candidate manifest. It neither installs `AGENTS.md`/`CLAUDE.md` in a project nor starts a harness. A later selected-file inspection verifies internal consistency without importing records or assigning authority. Project installation and actual target qualification remain separate work.

Implement the pure encoder and verifier first, then the bounded selected-file host boundary and native export/inspection workbench. Do not describe an unconnected core API as a working Export button. The initial format contains one artifact; multiple skills first pass through explicit composition and local review. Broader profiles, full provenance graphs, reimport and target change plans remain roadmap requirements.

## Exact format and limits

Version 1 consists of these bytes in order, with no padding or trailing data:

1. ASCII magic `RANGOON-INSTRUCTIONS-V1\n` (24 bytes).
2. Unsigned 64-bit big-endian canonical manifest byte length.
3. Unsigned 64-bit big-endian artifact byte length.
4. Exact canonical UTF-8 candidate-manifest bytes from the frozen compiler.
5. Exact artifact UTF-8 bytes, including any original BOM, CRLF, whitespace and final-newline state.
6. Sixty-four lowercase ASCII hexadecimal bytes containing SHA-256 of all preceding file bytes.

Manifest length is 1–32,768 bytes. Artifact length is 1–262,144 bytes and content must also meet the existing nonblank/no-NUL rule. Maximum total length is 295,016 bytes: 24 + 8 + 8 + 32,768 + 262,144 + 64. Bound the input before parsing, validate both lengths before allocation, use checked arithmetic/conversions, require the exact total, and reject truncation, trailing bytes, unsupported magic and invalid UTF-8. No compression, archive paths, extraction commands or executable metadata exist.

Manifest encoding is the existing versioned `serde_json` compact struct encoding: exact field order, standard string escaping, no BOM/extra whitespace/trailing newline. The decoder rejects noncanonical encodings, including otherwise equivalent key ordering or escapes. This is a deliberately narrow Rangoon format, not generic JSON canonicalization. Every known nullable field must appear explicitly. Unknown, duplicate and missing fields reject at every level; enum and integer types remain closed. Do not add `Deserialize` to public compiler report/output records merely to accept an external file. Use private wire records, semantic validation and canonical reconstruction.

The manifest embeds only existing revision/provenance references and an unauthenticated local review observation. It contains no original source/composition graph, revision creation time, current head, absolute path, current clock, account identity, credentials, or generated execution permission. The artifact's logical filename is fixed by the frozen profile, never an extraction destination.

## Pure API and verification

Add a `bundle` module to `rangoon-compile`, retaining its Rust 1.85 and no-I/O boundary. Use existing dependencies only.

- `encode_bundle(&CompilationReport) -> Result<EncodedBundle, BundleError>` accepts only a fully consistent candidate report. The returned structure contains exact `bytes` and an `inspection`. Reject unreviewed/blocked reports and mutated public report fields. Encoding must pass the same verifier and require its reconstructed compilation report to equal the supplied report; do not trust caller-controlled candidate IDs or manifest fields.
- `inspect_bundle(&[u8]) -> Result<BundleInspection, BundleError>` validates an untrusted file in memory. It does not mutate storage, consult the environment, load includes, install files, invoke a provider or grant authority.
- `BundleInspection` is serializable only, with camelCase fields in this order: `schemaVersion` (`rangoon.instruction-bundle-inspection.v1`), `bundleId`, `sha256` (whole-file digest), `byteLength`, `compilation` (reconstructed report), `verification` (`internal_consistency_only`), `authority` (`none`). This report is external-file evidence, never validated-workspace provenance.
- `bundleId` is `instruction-bundle:` plus SHA-256 of `b"rangoon.instruction-bundle.v1\0" || u64_be(file_byte_length) || complete_file_bytes`. The checksum trailer hashes only its preceding bytes. Candidate identity is recomputed from the manifest using the existing compiler framing; it is not another mutable field in the file.
- Fixed errors are `bundle_too_large`, `bundle_invalid`, `bundle_not_candidate` and `bundle_serialization_failed`. Return no raw JSON, source or path in errors. Oversized input/declared component bounds use `bundle_too_large`; malformed encoding, checksum or inconsistent candidate data use `bundle_invalid`; an encoder given blocked/unreviewed output uses `bundle_not_candidate`.

The verifier must check the checksum, exact canonical manifest, closed manifest schema, fixed profile digest/path, `authority: none`, exact artifact length and digest, selected revision content digest, IDs/title/parent/provenance shape, bounded local review timestamp and exact local reviewer enum. Match the profile digest against the two immutable descriptors; unknown profiles reject. Recompute ordinary revision identity from the capability/parent/title/content. Composition provenance can only be checked structurally because its graph is absent; never claim standalone graph validation. Review must be present. Regenerate the exact ordered diagnostics for the profile and empty requirements; any blocking diagnostic rejects. These profiles cannot create a candidate with nonempty structured requirements.

Recompute compilation identity and the canonical candidate manifest/hash/ID, then require the reconstructed canonical manifest bytes to equal the input. Reconstruct the full compilation report from these validated parts. Reuse compiler validation/identity helpers without inventing an original creation timestamp; that timestamp is absent from this format. Ordinary compiler input continues to validate its existing creation timestamp independently. Existing frozen compiler vectors must remain byte-identical.

Checksum and identities detect inconsistency and accidental corruption. A coherent attacker can replace the entire file and all digests. The verifier does not authenticate an operator, validate complete lineage, certify target behavior, prevent rollback, provide encryption, or establish runtime/security/government compliance. A checksum match is not a trusted signature.

## Native export integration contract

The subsequent native command accepts a bounded closed raw JSON request containing exact capability ID, revision ID, frozen profile and expected candidate ID, never a source body, review flag, manifest, file bytes or path. It shares the native operation guard. The UI must disclose plaintext export and require an explicit operator action from a fresh candidate report.

After the native save picker returns, resolve the requested exact revision through the validated workspace service and recompile it. Compare the fresh candidate ID with the inspected expected ID before creating any output. Missing/deleted/changed review evidence, blocked output or wrong ownership fails before write. Historical revisions remain valid explicit selections; never substitute a current head. Encode and write the same immutable post-picker compilation object. A later workspace mutation does not revoke this already validated snapshot; no live database lease is claimed. Cancellation creates no output and does not clear a usable report.

Require an absolute selected path and an exact lowercase `.rangoon-instructions` extension, use a neutral default filename, and exclusively create a new regular file. Final names must have a nonempty UTF-8 stem, no leading/trailing whitespace or final period, no control/reserved characters (`<>:\"/\\|?*`), and no Windows device basename (including suffixed device names and COM/LPT superscript-digit variants). Unicode names remain supported. On Windows, reject device namespace and arbitrary verbatim namespace prefixes (`Prefix::DeviceNS` and `Prefix::Verbatim`), `..` parent traversal and reserved/stream syntax in parent components as well. Normal disk/UNC paths may normalize interior `.` segments; any current-directory component retained by the path parser (such as in a verbatim path) is rejected. Ordinary disk/UNC and their explicit verbatim disk/UNC forms (`Prefix::Disk`, `Prefix::UNC`, `Prefix::VerbatimDisk`, `Prefix::VerbatimUNC`) are accepted with the same component checks; this accommodates selected long paths without permitting an arbitrary device namespace. These portable-name rules follow the [Microsoft naming reference](https://learn.microsoft.com/en-us/windows/win32/fileio/naming-a-file); they do not establish parent custody. Never overwrite an existing path, write an active instruction filename, or automatically create parents. Final symlink/reparse/special-file checks follow the established host boundary. Parent directories are not held or confined; a selected path is not a directory-capability grant. Cloud-synced locations, hostile parent replacement and privileged local users remain outside custody guarantees. Windows inherits destination ACLs; Unix creation uses owner-only mode, subject to the process umask.

The first write contract follows explicit direct-create semantics: `write_all` plus file `sync_all`; no atomic rename/rollback/directory-durability claim. A failed write/sync may leave a partial file. Do not delete or retry automatically after an ambiguous result. Return a fixed failure explaining that a file may remain and a new name is required. A later explicit retry reselects and revalidates everything. A success receipt identifies exact bundle/candidate IDs, whole-file digest and byte length, never an absolute path; it establishes completion of the stated write/sync operations, not future disk integrity or authentication. A lost response remains uncertain even if a complete file exists.

The host exposes `read_selected_instruction_bundle` (bounded bytes only; its caller must invoke the verifier) and `write_selected_instruction_bundle` (verifies bytes before creation). File errors use fixed `instruction_bundle_name`, `instruction_bundle_read_failed`, `instruction_bundle_exists` or `instruction_bundle_write_failed` codes; size/format failures keep `bundle_too_large`/`bundle_invalid`. No raw path or OS error is returned.

Native selected-file inspection reads at most the bundle limit plus one byte from a regular opened handle, invokes the pure verifier and presents its external-file provenance limits. It never imports or reviews a skill. UI command DTOs, states and tests must be frozen before this integration is enabled; core-only publication does not enable them.

## Acceptance evidence

Pure-format acceptance includes both profiles; reviewed ordinary and composition-reference records; deterministic independent framing/checksum/identity vectors; BOM/CRLF/Unicode/no-final-newline and maximum content; unknown/duplicate/missing/null fields; altered bytes/lengths/checksum/profile/path/schema/authority/review/IDs/diagnostics; negative/overflow/inexact quantities; noncanonical encodings; every truncated prefix and trailing data. Check coherent artifact swaps and internally rehashed manifest mutations, not only bad-checksum cases. Existing compiler vectors and tests must remain unchanged. Encoder tests must reject mutated public reports. Named formatting, tests, Clippy and a fresh independent read-only review precede publication.

Native integration additionally needs picker cancellation, stale selection/review changes during picker, busy operations, unchanged DB/session state, no overwrite, concurrent same-path writers, final-link/reparse/special-file behavior, parent-link limits, permission and size bounds, partial-write/sync failure, uncertain-result retry and receipt correlation. Real native GUI/IPC evidence is separate from source tests and synthetic binding checks. Exercise Windows, macOS and Linux; never relabel one host as all-platform qualification. Preserve keyboard focus, dark/light themes, responsive states and current Skills/composition drafts.

No license adoption, installer/release publication, engine/provider activation, project installation, deployment or grant submission follows from this contract.
